# 多市场账户与港股通记账（D208–D210）

- 来源：用户验收（2026-10-29）三条原话
  - 「A股账户，买入港股通的股票有问题」
  - 「比如 文-中国银河，需要录入买入的港股通 01021，代码没有提示港股通的股票信息。正常是否可以选择是否港股通，默认是A股的股票，但可以选择港股通」
  - 「如果是港股的账户，默认录入的是港股的股票，但可以选择美股、A股（沪股通/深股通）、...」
- 范围：`/portfolio`（开户、录入成交、成交记录）、`LedgerService` / `SimOrderRepo`、
  `akshare_hk` 代码表、`sams ledger account add`
- 纪律：先红后绿；每条修复都有一个「用户原话里那一屏会怎样」的测试

## 现状：三条根因叠在一起

1. **账户没有类型**。录入成交的市场下拉恒按配置字母序给 `A`，与「这个账户平时买什么」无关；
   港股账户每次都要手改，A 股账户想买港股通也只能在一个没有提示的下拉里找。
2. **跨币种没有「按汇率结算」的出口**。D207 只给了「先换汇成 HKD 再买」，而真实的港股通
   是券商在 CNY 侧按参考汇率直接扣款——用户手里没有 HKD 时，账本按「没有 HKD 现金」拒掉，
   那是记账规则对了、业务模型缺了一条。
3. **港股主档一次都没同步成功**（`symbol_master` 里 HK 0 行）：东财港股快照
   `stock_hk_spot_em` 连续 `RemoteDisconnected`，降级链上没有第二个港股代码表源。
   于是候选面板搜 `01021` 什么也没有，D206 的「另一个市场有这只票」也永远不成立——
   A 股账户把 01021 记成 A 股时，没有任何一道闸说话。

用户库里的那笔 `A/01021`（1400 股 @8.205，40 元费用）不在这里悄悄改：它是用户的数据，
出口是页面上已有的「撤销」，按正确的市场重记一笔。本轮把「重记」这条路修通。

## D208 账户有主场：开户选 A 股 / 港股 / 美股账户

- `sim_accounts` 加一列 `home_market VARCHAR NOT NULL DEFAULT 'A'`（迁移 `0026`）。
  已有账户一律是 A：它们都开在只有 A 股记账的场景里，默认值就是它们的事实。
- `Account.home_market`、`SimAccountRepo.open(..., home_market="A")`、
  `LedgerService.open_account(..., home_market=...)`：服务层校验它必须是**已配置市场**，
  不是就拒（与成交推币种同一道闸，未配置市场的币种推不出来）。
- 开户表单那一个下拉：`A 股账户 / 港股账户 / 美股账户`，值交给 `home_market`。
  CLI 给 `sams ledger account add --home-market HK`（默认 `A`），`--json` 与两屏打印都带上它。
- 录入成交的默认值改成「**第一个账户的主场**」而不是字母序第一个市场；账户下拉每一行带
  `data-home-market`，换账户时页内脚本把市场切到新账户的主场（用户仍可再改）。
- 市场下拉的文案按语境给：`A 股 / 港股通（HK）/ 美股（US）`。港股通不是一个市场，
  是 A 股账户买 HK 的那条通道——记账的市场仍是 `HK`，结算在 D209。
- **为什么不复用 `market_scope`**：那一列从来没被读过，含义是「这个账户准备做哪些市场」，
  与「默认选哪个」是两件事；把默认值塞进去，下一个人会把它读成权限或约束。
- 报告币种仍是全局 `settings.report_currency`（CNY）。「港股账户」改的是默认市场，
  不是记账本位币：把报告币种做成逐账户，换算、汇总与展示全要跟着分叉，登记为待办。

## D209 跨币种成交：填了汇率就按报告币种结算

「标的一直用自己的币种记账」（§5.4 规则 1）不变：订单的 `currency` 仍是标的币种，
费用也仍是标的币种。变的是**现金从哪个口袋出**：

- `buy/sell/record_fill` 的参数 `fx_rate_ref` 改名为 `fx_rate`，语义扩成
  「这笔成交由券商按这个汇率（标的币种 → 报告币种）结算」：
  - 不填 → 与今天完全一样：从标的币种现金扣/收；买入没有该币种现金就拒（D207 那句）。
  - 填了且标的币种 ≠ 报告币种 → 现金动**报告币种**：
    买入扣 `(数量 × 价格 + 费用) × 汇率`，卖出收 `(数量 × 价格 − 费用) × 汇率`；
    订单同时写 `fx_rate_applied = fx_rate_ref = 汇率`。结算那一刻的汇率就是这笔的
    基准汇率，盈亏的价格段/换汇段因此拆得开（§5.4 规则 2）。
  - 填了但标的币种 = 报告币种 → 拒：`A 601088 以 CNY 计价，账户的报告币种也是 CNY：不需要汇率`。
    静默忽略一个用户填的数，正是这套系统一直在防的那类错。
- 买入的现金前置检查按**实际结算币种**查：填了汇率看报告币种，没填看标的币种；
  余额不足仍由 `adjust_cash` 那句拒绝给出确切数字，不在这里另写一套。
- **撤销**按 `fx_rate_applied` 反做：有值就动报告币种（`(gross ± fee) × rate`），
  没有就动标的币种。撤销之后现金逐分回到成交之前，与 D205 的承诺一致。
- 网页录入表单新增「汇率（1 标的币种 = ? 报告币种）」一格，默认值按三句话决定：
  - 同币种：留空，提示「不需要汇率」；
  - 跨币种且账户**已有该标的币种现金**：留空（保持 D207 的「换好了就花换来的钱」），
    提示「要以 CNY 结算就填汇率」并给出库里那条预填值；
  - 跨币种且没有该币种现金：预填 `_rate_hint` 那条（含日期与出处），提示「留空则从 HKD 现金扣」。
  换账户/换市场时脚本按同一规则重算；用户手改过的值不覆盖（用 `data-auto` 记住上一次自动值）。
- 成交记录在「币种」旁边把结算说出来：`按 7.2100 折 CNY 11,527.00`。
  否则 CNY 少了一笔、订单上写 HKD，读账的人找不到这两条流水之间的关系。
- CLI `--fx-rate` 的说明改成「标的币种→报告币种汇率：填了就从报告币种现金结算，
  不填就从标的币种现金结算」，与网页同一个含义，不留两套。

## D210 港股代码表有两个源；代码形态在写入口把关

1. **代码表降级**：`akshare_hk_symbol_list()` 先问东财 `stock_hk_spot_em`，抛错或空表时
   退到新浪 `stock_hk_spot`（实测 2808 行，列名 `代码/中文名称`，重命名成 `名称` 再交给
   `normalize_symbol_list`）。两个都失败就抛最后一个错，由 `classify_error` 记源健康——
   「东财挂了」与「港股没有代码表」不是同一句话。两个取数函数做成可注入的参数，
   让降级顺序能在不碰网络的情况下测。
2. **写入口的代码形态闸**（`record_fill`，归一之后）：
   - `A`：必须是 6 位数字；5 位数字的拒绝句点名港股通：
     `A 股的代码是 6 位数字，收到 01021：5 位数字通常是港股（港股通请把市场选成「港股通（HK）」），或代码少写了一截`。
   - `HK`：归一一律 5 位数字（`700`→`00700`）；归一后不是 5 位数字就拒。
   - `US`：不猜形态（`BRK.B` 这类形态没有可靠的规则），只要求非空。
   **只闸写入口，不改 `canonical_code` 的读路径**：库里已有的 `A/01021` 还要能读出来、
   能在成交记录里点「撤销」；在归一函数里加校验会让那一屏直接 500。
3. **跨市场闸看全主档**：`SimOrderRepo` 的 `symbols` 注入从 `symbols` 表（行情同步顺带写、
   HK 只有 1 行）换成 `symbol_master`（代码表同步的完整结果）。港股表同步成功后，
   A 里记 `01021` 会先被 D206 那句「A 里没有 01021，但 HK 有 01021」拦住；
   代码形态闸是主档为空时的第二道保险——本轮之前正是两道都没有。
4. 成交记录的名称查找同样先读 `symbol_master`，读不到再退回 `symbols`：
   港股通成交要显示「中国银河」，而不是一行只有代码的成交。

## 共用

- `Order` 增加 `fx_rate_applied`（读出 `sim_orders` 那一列）；成交记录与撤销都读它。
- `_NOTICES` 不变；开户表单被拒时回填 `home_market`，与 D197「一张表被拒不改另一张」一致。
- `sams run once --job` 的帮助文本补上 `symbol_master`：它早就在注册表里，
  帮助里没写，等于告诉运维「这个 job 不存在」。

## 测试

- 仓库：开户默认主场 A、可存 HK；跨币种买入填汇率 → CNY 现金减少、HKD 不动、订单两列都是汇率；
  卖出同理；同币种填汇率被拒；填了汇率而报告币种现金不足 → `adjust_cash` 那句；
  撤销按汇率反做回 CNY；`A/01021` 被代码形态闸拒且一行订单都没写；`HK/601088` 被拒；
  主档有 HK 01021 时 `A/01021` 被 D206 那句拒。
- 服务：未配置的市场做主场被拒；其它人的账户开不了（既有）。
- 网页：开户选港股 → 该账户排在第一个时录入表单默认市场是 HK；市场下拉有「港股通（HK）」；
  港股账户没有 HKD 现金时汇率格预填、有 HKD 时留空；HK 01021 带汇率买入后 CNY 余额按汇率减少；
  不带汇率且无 HKD 现金 → 仍是被 D207 那句拒；A 01021 → 400 且提到港股通；
  成交记录出现「按 … 折 CNY …」；港股候选面板在主档有行时显示名称。
- 数据源：东财抛错 → 新浪行被归一成 `code/name`；东财空表 → 同样退到新浪；
  两个都空 → `EmptyResponse`。

## 上线后要做的一次数据修复（不是代码）

1. `sams run once --job symbol_master --market HK` 同步港股主档，确认 01021 的名称与
   `symbol_master` 行数（期望约 2808）。
2. 用户在 `文-中国银河` 的成交记录里撤销 `A/01021`，再把市场选成「港股通（HK）」、
   填上券商结算汇率重记一笔。库里那行无名的 `symbols(A, 01021)` 留着不影响记账，
   由主档同步与后续清理处理。

## 登记为待办（本轮不做）

1. 逐账户报告币种（港股账户以 HKD 报告）：换算、汇总、`fx_pnl` 与展示全要分叉。
2. `fx_rate_applied` 与 `fx_trades` 的对账：M5 一起做。
3. B 股（900/200）与港股人民币双柜台在表单里的汇率预填：币种按代码推定，表单只认识市场。
4. 港股通标的名单与额度：不是记账问题，是行情/规则源的问题。
5. 港股通费用模型（印花税、交易征费按笔算）：费用目前由用户填，不替券商算。
