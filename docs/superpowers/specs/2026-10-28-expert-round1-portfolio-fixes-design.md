# 专家验证第一轮：持仓页可用性修复

> 来源：2026-10-28 交易专家试用报告（C1 持仓/账本）。本轮只修 P1：网页端开不了户、
> 账户卡拆不出「还能买多少」。其余 P2/P3 登记在文末「推迟」，不在本轮动。

## 1. 缺陷与修法

### 1.1 网页端没有开户入口（P1-2）

`sams serve` 独占 DuckDB：CLI 的 `sams ledger account add` 在服务运行时会撞库锁，
所以空态里那句「去跑 CLI」是一条死路。持仓页现在自带两张写表单：

- `POST /portfolio/accounts`：账户名 + 可空的起始资金。起始资金直接记进报告币种，
  理由写「起始资金」；金额为负拒在 400。
- `POST /ledger/cash`：账户、入金/取出、币种、金额、理由。金额必须大于 0，
  币种取「报告币种 + 各市场币种」的下拉，免得手打成不存在的代码。

两句写入都走 `LedgerService` 已有的 `open_account` / `deposit` / `withdraw`，
页面不另开一套账；`DatabaseLocked` 照旧交给全局处理器答 503。

### 1.2 账户卡只有「合计」，拆不出现金与市值（P1-3）

`PortfolioService.summary` 早就算好了 `cash_by_currency` 与
`position_value_by_currency`，只是页面没端出来。现在账户卡第一张表是：

| 现金（可用） | 持仓市值 | 总资产 | 价格盈亏 | 换汇盈亏 | 已实现 |

逐币种列出（多币种各占一行），空档写「—」而不是 0。
看板 `overview.html` 同一口径：第一格改叫「总资产」（它是现金 + 持仓市值，
不是市值），第二格改叫「浮动盈亏」（`price_pnl_report + fx_pnl`，不含已实现）。

### 1.3 成交没有日期（P2，顺手修）

CLI 的 `--on` 是必填，网页却只能记「现在」。补录一笔上周的成交会落在今天，
而屏幕上和正确的那天长得一样。表单新增 `on`（`type=date`，默认今天）：

- 空串 = 按现在（保持原有行为）；
- `YYYY-MM-DD` = 那天**市场本地 15:00**（`market_cfg(...).zone()`），与 CLI 同口径；
- 解析失败 → 400 并回填原值，不静默改成今天。

### 1.4 两张表单共用一个回填 dict

成交被拒时，现金表单的「方向」会被写成 `buy`/`sell`；现金被拒时，成交表单会拿到
`withdraw` 这类它不认识的选项。三张表单（开户/现金/成交）现在各有一份回填 dict，
一张报错不冲掉另一张的值。

## 2. 决策

- **D194 持仓页自带开户与现金入口。** 服务独占库时 CLI 写不进去，页面的空态
  必须指回页面上的表单，而不是一条跑不动的命令。
- **D195 账户卡拆成「现金（可用）/持仓市值/总资产」，看板同口径。**
  `total_report` 一直是总资产；把它标成「总市值」会让人以为整数都是票。
- **D196 网页成交带成交日，按市场本地 15:00 记。** 非法日期 400，不静默用今天：
  错的那天在屏幕上与对的一天一模一样。
- **D197 每张写表单各有回填 dict。** 一张表单的错误响应不能改写另一张表单的当前值。

## 3. 测试

`tests/web/test_portfolio_web.py`（21 条）覆盖：

- 网页开户（带/不带起始资金）、入金、取出、超额取出保留表单；
- 现金与持仓市值分开列，合计仍是总资产；
- 成交日回填（`2026-10-20` 记在当天）、非法日期 400 且不回落到今天；
- 被拒成交保留全部字段、无账户时提示指回页面上的开户表；
- 每个账户持仓空态、逐行行情日、两账户同标的各出现在自己卡下；
- 大额数量千分位、论点下拉写「市场 代码 · 状态」。

`tests/web/test_dashboard.py::test_the_account_column_says_assets_not_market_value`
钉住看板两格的措辞。
