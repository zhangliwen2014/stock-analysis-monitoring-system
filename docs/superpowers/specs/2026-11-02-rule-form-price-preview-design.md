# 建规则时看得见现价 + 保存前试算（R-22 剩余）设计

日期：2026-11-02
来源：`2026-10-31-expert-testing-round2.md` R-22（P2，波段角色，`/rules/new`）
> 对象引用手填「A/000001」或「*」；止损价旁无现价；保存前不能试算 → 建规则易错，错了删重建

R-22 拆成三件事，第一件已经落地，本设计只管后两件：

| 子项 | 状态 |
| --- | --- |
| 标的下拉复用搜索候选 | 已做（#361，`/api/symbol-search/pick` 挂在每个标的输入框上，`rule_form.html` 那一格也在内） |
| 侧栏显示现价与距止损 | 本设计 §2 |
| 保存前 dry-run | 本设计 §3 |

## 1. 目标与非目标

**目标**

1. 打开 `/rules/new?kind=...&target_ref=A/600519`（个股页那个「新建止损」链接就是这一条路）时，
   屏幕上方直接写着这只票此刻该显示的价、哪一天、哪个源，而不用先保存再去列表看。
2. 填的是**绝对价**那一格（`unit="元"`：`stop.fixed.price`、`price.cross_below.price`、
   `price.cross_above.price`）时，旁边立刻说清这条线在现价上方还是下方、差多少百分比。
3. 保存之前能拿这一屏正在填的参数判一次，看见「真跑会命中哪几只、现值/阈值各是多少、
   或者为什么判不了」——而且**这一趟什么都不写**。

**非目标**

* 不做实时刷新：现价一格按「进这一屏 / 点一次试算」读一次，与其余五页同一口径（S0-E）。
  轮询要的是另一件事（行情板属于调度进程，页面不该自己敲源）。
* 不动求值口径：判据、除权搬家、过滤器、三档全走引擎原本那条路，页面不加第二套算术。
* 不做仓位/股数建议（评审 §10「去建议化」仍然有效）。

## 2. 现价参考（表单上方那一格）

**读哪一份**：`web/quotes.py` 的统一读模型，与看板/自选/个股/持仓/规则列表同一套
（盘中是过闸的报价，休市或停更回落 `bars_daily` 最后一根不复权收盘）。列表页已经在用它
（`_list_page` → `_quote`），表单页只是补上同一次读取。取数点：`_form_page` 里
`quote_reader(ctx, web.core, now)`，`now` 用 `web.core.clock.now_utc()`，与市场时区那条
换算同一来源。

**什么时候有现价**：只有挂在**单只标的**上（`target_type=symbol` 且 `target_ref` 能拆成
`市场/代码`）才谈得上「这一只的现价」。其余形态各自说一句人话，不留空白：

| 形态 | 屏幕上那句话 |
| --- | --- |
| `symbol` + 合法引用 + 有价 | `贵州茅台 A/600519 现价 1,392.05 元｜10-30 收盘｜不复权 · akshare` |
| `symbol` + 合法引用 + 无价 | `A/600519 库里还没有日线：先跑 sams sync daily --market A --code 600519（休市/无行情一并说明）` |
| `symbol` + 引用写坏（没带市场前缀、野市场） | `对象引用要写成 市场/代码（例如 A/600519）——现在这串读不出一只票` |
| `watchlist` / `position`（引用是 `*`）/ `thesis` | `这条挂在{那一类的中文名}上：没有单一现价，试算会逐只给出现值`（中文名取自 `display.TARGET_TYPE_LABELS`：自选清单 / 持仓 / 论点） |

币种必须在这句话里：同一格里 `HK/00700` 的 40.4 是港元、`US/AAPL` 的 230 是美元，
漏掉币种的那一格「现价」会被读成同一个钱。单位走 `price.unit`（`currency_label`），
B 股与港股双柜台的例外由 `currency_override` 负责，页面不认代码前缀。

**百分比那一格不换算成价**：`stop.pct` 的 8% 说的是**成本**下浮 8%，`stop.trailing` 的
基准是**持仓期最高价**，`tp.tiered` 的分档是成本到目标价的进度——三个都不是现价。页面要是
拿现价乘一下印在旁边，说的是「你的线在这儿」而引擎算的是另一个数，这类错只有除权日才露出来。
所以只有 `unit="元"` 的三个绝对价参数参与换算，其余参数的相对关系交给 §3 的试算结果
（引擎的 `value_text` / `threshold_text` 本来就成对给出这两个数与它的口径）。

**方向与距离怎么说话**（`price` 为现价，`line` 为填入的绝对价）：

* `gap = (line − price) / price × 100`，分母用现价：「还要跌多少才碰到这条线」是
  交易的人问的那句话。
* `line > price` → `止损价 1,400.00 元：这条线在现价上方 0.57%`。
* `line < price` → `止损价 1,200.00 元：这条线在现价下方 13.80%`。
* `|gap| < 0.005%` → `这条线就是现价`：同一个数按两侧说都会说出半句假话（「上方 0.00%」）。
* 主语固定是**那条线**，不是现价：「这条线在现价上方」与「现价在线下方」是同一件事的两种
  说法，混用会让人把方向读反，而方向读反的止损线是反向的。
* 只说位置与幅度，不说「会命中」：`stop.fixed` 出 pre/hit/urgent 三档（`Template.stages`），
  哪一档是引擎的事，写在 §3 的结果里。把「已经破了」印在旁边会让人以为屏幕上那一条就是
  告警正文，而那条正文还要过过滤器、冷却与状态跃迁三道闸。
* `price` 为 `None` 或 `≤ 0` 时那一格整段不出现（不写「现价 —，距离 nan%」）。

**顺带补的一行**：填好参数的表单分支现在没有返回链接（只有「选一种规则」那一屏有）。
和「看完选股回不去」同一类毛病，这一屏补 `← 返回规则列表`。

## 3. 保存前试算

### 3.1 只读承诺写在接口上，不写在按钮的措辞上

新增两个端点，都要求 CSRF，都要求登录：

| 端点 | 表单来自 | 参数合并 |
| --- | --- | --- |
| `POST /rules/preview` | `/rules/new` 那张表 | 就是这一屏填的（缺的必填项按创建同一句拒） |
| `POST /rules/{rule_id}/edit/preview` | 编辑那张表 | 库里那份打底、刚填的那几格盖上去（`{**stored, **touched}`）：保存那一路「一格都没填」交的是 `None` = 整包不动，而试算要的是一份判得动的草稿，留空在这里说的正是「这一项按库里那份判」 |

按钮用 `formaction` 挂在同一张 `<form>` 上（`试算（不保存）`），保存那颗的 `action` 不变。
一张表两个出口，比复制一屏表单少一处会分叉的地方。
试算那颗排在前面：回车落在表单里的第一个提交按钮上，落的得是不写任何东西的那一次
（与列表页「试算 / 判一次」同一顺序，D231）。

编辑页也要有，理由具体：列表页那颗「试算」判的是**库里那一份**参数。人正在把止损线从
1400 改成 1250，按下旧按钮看见的是 1400 的结论——那一句比没有更贵。

### 3.2 三层各加一个窄口子

**仓库层** `RuleRepo.build(...)`：把 `create` 已有的 `_validate(...)` 结果装配成一条 `Rule`，
**不 INSERT**。`_validate` 是创建与更新共用的那一套判据（模板收不收这个 target、必填参数、
野键、级别名单、冷却非负、`_require_target_shape`、`_require_thesis`），草稿必须走同一套：
两处各写一遍迟早分叉成「命令行说不行、试算说会响」。id 用一个明写的哨兵 `"draft"`，
`params_on` 取今天（与 `add` 同一句：人此刻填的价属于此刻的价空间）。

**服务层** `RuleService.draft(user_id, ...) -> Rule`：跑 `add` 在仓库之前的那四道检查
（`_require_user`、`_require_account`、`_require_channels`、`_require_configured_market`），
再调 `rules.build(...)`。**不调 `_bump()`**：那一响是给「写面动过」用的（盘中缓存失效闸），
一次试算什么都没改，bump 会让盘中那一趟白白重读整张快照。

**引擎层**：把 `check` 里 `selected = self._select(...)` 之后的循环抽成私有
`_judge(selected, *, day, now, market, dry_run, quotes, is_test)`（参数名沿用 `check`
局部的那几个：抽出来的是同一段代码，不是重新设计一遍），`check` 变成
「校验参数 → 选规则 → `_judge`」。新增

```python
def preview(self, user_id: str, rule: Rule, *, as_of: date | None = None,
            market: str | None = None) -> RunReport:
```

内部 `dry_run=True` 恒成立，`intraday=False`、`quotes=None`、`is_test=False`。
`dry_run` 不在参数表上：一个能被调用方忘掉的「只读开关」不是承诺。

`_judge` 抽出来后 `check` 的既有语义一字不动（`market` 归一、`intraday`/`quotes` 那对
成对校验、`_select` 点名绕过 `enabled`），调度器与 CLI 走的是同一条新路径。

### 3.3 草稿为什么判得出、又不会污染状态

`dry_run` 那条路上引擎一处写都不做，这一点由代码本身保证，试算是它的第一个用户：

* 判到而 `verdict is None` 时翻回 clear 那一句在 `if not dry_run and not is_test` 里；
* 静音期间记状态在 `if not dry_run` 里；
* 命中后写 `alert_states` 排在 `_dispatch` 成功之后，而 `dry_run` 分支在它前面就
  `return self._raised("", ...)`——`alert_id` 是空串，屏幕上「告警」那一列因此只能是
  「试算：真跑会写一条告警」（`rule_check.html` 既有措辞，直接复用）。

草稿的 `rule.id == "draft"`，`states.get(user_id, "draft", ...)` 永远为空，于是预览看到的是
「这条规则第一次响会怎样」，而不是「因为它昨天响过所以今天被吞了」。这是对的：试算问的
就是刚填的这条线。冷却同理不参与（没有历史可压），过滤器照常跑——那四道闸
（开盘前后 5 分钟、行情超过 3 天、停牌、已有未处理告警）判的是市场状态与别人的告警，
与这条规则新不新无关，所以「命中 0」旁边会印上被谁压住的那句话。

### 3.4 判的是哪一天的价，屏幕要分开写

`intraday=False` 那一趟用最新一根日线收盘判（与调度器的收盘趟同一口径）。盘中打开这一屏时，
§2 那一格显示的是过闸的盘中报价，而试算结果里的 `value_text` 是收盘价——两个数会不一样。
不掩盖：结果面板头部那句 `评估日 X` 之后紧跟一句来路说明——`这次试算读的是最新一根日线收盘，
没读盘中报价：保存后调度器会按实时报价继续看。`；命中那一行自己带 `数据 YYYY-MM-DD`
（`Raised.data_on`），所以「这个现值属于哪一天」在同一个数旁边就看得见。
把两边强行改成同一个数需要让预览走行情板，而行情板在 `serve` 进程里由调度线程喂，
页面拿它做预览会把「没轮到轮询」读成「这只票没价」（§5.3 那套新鲜度闸的取舍不适用于一屏草稿）。

### 3.5 结果面板复用同一摞Markup

`rule_check.html` 那五摞（命中/压住/判不了/这条规则没跑/什么都没到）抽成
`templates/partials/rule_outcome.html`，由 `rule_check.html` 与 `rule_form.html` 各自
`include`（`partials/` 是这一层既有的目录：`quotes.html`、`screen_switches.html` 都住在里面）。
两处读同一份行数据：`_check_page` 里那套 `raised/suppressed/skipped/blocked` 装配
抽成 `_outcome_rows(ctx, user, report, *, lead="")`，表单的试算出口调它并把 §3.4 那句来路
说明交进去。理由与 `_validate` 一样：同一次求值在两屏说两种话，下一版只会改其中一屏。

「试运行 / 真跑」那一句只有一份，两屏同一措辞（`tests/web/test_rules_web.py` 里那句
`"试运行" in page.text` 的断言钉着它）：用户不需要为同一个动作学两句话。

### 3.6 出错时表单还在

`draft()` 抛 `SamsError`（少必填项、`stop.pct` 挂在自选上、级别不认识、引用没带市场前缀、
别人的账户、未配置的市场）时：**不跑引擎**，按 `rule_create` 被拒那条路重新渲染表单
（原文回填 + 那一句话 + §2 的现价格），状态码 400。`DatabaseLocked` 照旧原样抛出交给
全局 handler 答 503——库被调度线程握着不是「你填错了」。

判得动但一个对象都没展开（自选为空、持仓为 0）时不空转：结果面板走「什么都没到」那一摞，
并在头部把 `看了 0 个对象` 印出来（`judged`），0 是个答案，不是错误。

## 4. 测试（红→绿，一条行为一个循环）

`tests/web/test_rules_form_price.py`（新文件，避开 1023 行的 `test_rules_web.py`）：

1. 从个股页那条链接进来（`GET /rules/new?kind=stop.fixed&target_ref=A/600519`）屏幕上
   出现现价、单位、数据日与来源。
2. 库里没有日线的那只票：说「先跑 sams sync daily …」，不出现「现价 —」。
3. `target_ref=600519`（缺市场前缀）：说引用读不出票，不 500。
4. 收盘 1392.05 而 `price=1400`：那一格印「这条线在现价上方 0.57%」；`price=1200` 时换成
   「这条线在现价下方 13.80%」。（两句百分比由设计时按喂进去的收盘算出来再写进断言：
   屏幕上的那一个数是 `:.2f` 格式化过的，拿同一个公式在测试里再算一遍只会测到自己。）
5. `stop.pct` 那一屏不出现任何按现价换算的话（钉住 §2 那条「不换算」——最容易顺手加错的一格）。
6. `POST /rules/preview` 命中时：200、表单仍在（`name="param_price"` 还在）、结果里出现
   现值/阈值/数据日，且**库里 `alerts`、`alert_states` 一行都没多**，`rules` 表也没多一行
   （断言按读库而不是按「页面没说已保存」）。
7. 预览的 `dry_run` 恒真：给 `RuleEngine.preview` 打桩，断言引擎收到的那条判据是只读，
   且 `is_test` 没被偷偷设成 `True`（演练告警会落库，绝不能是试算的副作用）。
8. 少填必填参数：400、那句话在屏上、`param_price` 的原文回填、引擎没被调用。
9. 别人的账户：`draft()` 拒，页面 400，不落一条规则。
10. `POST /rules/{id}/edit/preview` 用**刚改的**那条线判：收盘 1100、库里存 1250、表单填
    1400 → 阈值那一个是 1400.00 CNY；留空不填 → 回到库里那份 1250.00 CNY，而 `rules` 表里
    的参数仍是 1250（钉住 §3.1 编辑页为什么要自己那颗按钮，也钉住试算不落库）。
    （两个数都选在收盘上方：`stop.fixed` 判的是「现价 < 线」，反着选会得到一摞「都没到」，
    那一屏测不到阈值取自哪一份。）
11. CSRF：两个预览端点无 token 一律 403（与 `check/remove/demo` 同一批）。
12. 表单分支出现「← 返回规则列表」。
13. 冷却那一格敲汉字：400 回到表单（`_cooldown` 的兜底位置与保存那一路一致），不是一屏 500。

引擎与仓库的三条新口子各钉一测，不靠页面代理（都追加进既有文件：那里已经有一套真的
repo / 服务 / 引擎，新口子与旧口子共用同一套装配）：

* `tests/storage/test_rules_repo.py::test_a_draft_is_refused_by_the_same_rules_as_a_created_one_and_writes_nothing`：
  `build()` 校验与 `create()` 同一套（同一个野参数键两边同一句话），且不落库。
* `tests/services/test_rules_maintenance.py::test_a_draft_is_checked_like_an_added_rule_and_writes_nothing`：
  `draft()` 走 `add` 那四道检查、`params_on` 取今天、不写一行。
* `tests/services/test_version_bumps.py::test_a_draft_for_the_preview_bumps_nothing`：
  一次试算不动版本闸（拿那个会记账的假 `versions` 断言一次都没响）。
* `tests/services/test_rules_engine.py::test_a_draft_is_judged_with_the_same_numbers_and_writes_no_rows`：
  `preview()` 判出的那两个数与 `check()` 同一口径、`dry_run` 恒真、`alert_states` 没写、
  发送与命中记录一次都没被调用（`_judge` 抽出后 `check` 的既有语义由该文件其余各条守着）。

## 6. 明确不做

* 现价自动轮询、盘中预览（走行情板那一趟）、把百分比参数按现价换算、多标的批量草稿、

  承诺比这一点点方便值钱。已有 `/rules/demo` 负责「整条链真跑一次」这件事。
