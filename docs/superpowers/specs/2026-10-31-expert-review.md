## 2. 三方共识（按优先级）

1. **一价一 as-of 是第一前置**：展示用收盘优先、盘中显式切换；规则/告警判定仍用盘中最新价但标 `price_kind`。展示与判定分离，不是二选一。
2. **决策卡先做 5–6 格，不做 10 格**：标的状态、现价与价值区间位置、失效价、目标区间、赔率区间、结论 + 3 条证据；as-of 附在每个数字旁。胜率、精确仓位暂不上卡（A 股仅 121 根日线，n<30 恒成立）。
3. **结论改四态 + 持仓侧**：`不追 / 等价格 / 证据不足 / 可分批建仓` 用于未持仓；`持有 / 减仓 / 退出` 用于持仓。优先级：证伪 > 止损触达 > 数据或样本不足 > 价格区间。`价格高于目标` 叫「不追」，不等于标的变差。
4. **赔率给区间、扣成本、防自证**：`R_low=(T−P_high−c)/(P_high−S+c)`，`R_high` 用 `P_low`；T 与 S 的方法标签必须不同源；分批要求 `R_low≥2`；成本 A 0.3% / HK 0.6% / US 0.2%；跳空按 `min(S, 开盘)` 成交；止损距离 `< max(3%, 1×ATR14)` 判「止损过近，R 无效」。
5. **胜率的诚实口径**：参数冻结 + walk-forward；按波段冷却（≥持有窗口）后报「独立样本 n」；n≥30 且独立波段≥15 才给百分比；EV/凯利用 Wilson 下限；样本不足只显示「样本不足」。退市样本缺失必须披露幸存者偏差。
6. **硬闸**：bars 为空或 <300 根、报价超期（A/HK 3 个交易日、US 2）、财务超期（A 120 天 / HK 200 / US 100）时，卡片只出「数据不足，不出结论」，禁 R/胜率/仓位。
7. **告警去重看状态跃迁**：按 `(rule_id, account_id, is_test)` 存 `last_state`，只发跃迁；`bar_ts` 仅作证据，不进唯一键（否则每天重复、state 内漂移被吞）。补「连续 N 期方向 / 距阈值 <X%」趋势规则，摘要列「接近阈值」。
8. **摘要在各市场收盘后 30 分钟**，分持仓/自选/观察；前两周每日心跳，之后仅变化 + 周一一条；纳入 T-1 未处置告警（按标的最多 1 条）；源失败显示「数据未更新」。
9. **复用而非新建**：`theses` 已有 entry/stop/target/reward_risk，不建 `thesis_plan`，只补 `plan_version/plan_method`；行业复用 `symbols.sector` 与 `company_profiles.industry`，不建行业表；`nav_daily` 暂缓（先补 `cash_moves.kind`、分红、FX 固化）；`risk_policy` 用 `users.risk_json` 或小表。
10. **去建议化**：全部改条件句；仓位只给「数学上限，非建议」；显示对应金额与跌破失效价的亏损额；禁单一目标价、单一 R、精确股数、n<30 百分比。

## 4. 工程修订

- 迁移从 `0033` 起，只增 nullable 列或新表，不改历史文件。
- `thesis_assumptions` 加 `evaluated_period/source`；`alerts` 加 `trigger_bar_ts/dedupe_key`；`screener_presets` 加 `last_run_at`，新命中比对 `scan_results` 而非只看时间戳。
- 告警唯一键 `(rule_id, account_id, bar_ts, state, is_test)`；同日多用户各一条；测试告警不计数。
- 调度保持串行；新闻/回测/NAV 批量写分块提交，回测走离线 CLI，禁止外部进程开库。
- 港美 bars 修复顺序：源链/代码映射 → 裸价标注（数据层带 `price_basis`）→ 补 corp_actions → 切复权。
- 编码修复：严格 roundtrip、仅无 charset 时修、排除密码/CSRF，双路径回归。

## 5. 明确不做（评审后仍不做）

实盘下单；社区/跟单/投顾；实时 tick/Level-2；情绪分与「利好/利空」标签；DCF 单一目标价；5900 条件式选股；精确仓位/股数；`nav_daily` 在账本补齐前物化；原生 App。

## 6. 遗留争议与裁决

| 争议 | 裁决 |
| --- | --- |
| 默认价格口径 | 展示收盘优先，盘中显式切换并标延迟；判定用盘中最新价但标 `price_kind` |
| 是否给仓位数字 | 只给「数学上限」分档（0/≤3%/≤5%/≤10%）+ 金额与失效亏损，不给精确百分比/股数 |
| 胜率口径 | 同规则同参数、独立波段、walk-forward；样本不足不显示百分比 |
| 舆情落地 | 公告/新闻入库 + 关键词 + 原文 + as-of；无源灰显；不做情绪分 |
| 组合 NAV 起点 | 从成交完整之日起算，之前标「不完整」；不倒推 |
| 港美优先级 | 先港（已有持仓/估值注册），再美 |

说明：

- S2 实机重启暴露并修掉一个运维缺陷：`kill -TERM` 后 uvicorn 会把 SIGTERM 恢复成默认处理器再抬一次，进程直接结束，收尾代码走不到；而正常退出又不会让心跳过期，导致 5 分钟内重启时调度线程被上一世的新鲜心跳挡死且无提示。修法两处：迁移 0037 给心跳加 `stopped_at`，循环收工标停（守卫只看未停的那一行）；`sams serve` 跑 uvicorn 期间把 SIGTERM 设为忽略，让重抬的那一次落空。实机验证：停服后心跳有停止标记，1 秒内重启调度线程照常认领，`/healthz` 的 `scheduler.stale=false`。
- S3 全量回归暴露并修掉一个会话心跳缺陷：`_active_ok` 用墙钟判断「现在」，签发心跳却用注入时钟；冻结/回放时钟的会话在真实时间走过闲置窗口后会凭空失效。现在两边同读 `core.clock`，并补测试把「2020 年的冻结时钟登录后仍能进首页」钉住。同一轮把 `sams/datasource/news.py`（数据列集与空帧，不是适配器）补进 `_NOT_ADAPTERS`，让「包目录里每个模块都必须注册实现」的守卫回到真实。
