# 能力评审：比券商 App 缺什么、该补什么（D232）

用户反馈「功能还比不上普通券商手机 App」。这份文档不是照着 App 的功能清单往下抄，
而是请四类实践者各自回答同一个问题：**一个认真的个人投资者，每天真正会用到、
而 SAMS 现在没有或做错的是什么。** 结论：短板不在功能数量，在三条断掉的决策链。

- 组合层：账本只回答「每笔赚亏」，不回答「我在赌什么、现在价格是多少」。
- 证据层：论点是叙事，不是可证伪的假设；估值给了目标价，没给价值区间。
- 入口层：查一只票要先绕进「自选」；看板、持仓、个股各用一套价格。

券商 App 的很多功能（Level-2、龙虎榜、社区、投顾、打新、两融、期权）对本系统是负价值
或独立资产类别，明确不做（§5）。

## 1. 方法

四份独立评审，各自先读代码与设计文档，再给结论：

| 视角 | 核心主张 |
| --- | --- |
| 价值投资 | 缺「证伪台账、内在价值区间、配置与买入闸」；少看盘多看生意 |
| 短线交易 | 持仓盈亏按昨收算、个股页打开即冻结、无盘口、无盘中异动榜 |
| 组合管理/风控 | 缺合并暴露与集中度、日频 NAV/回撤、仓位与再平衡、业绩归因 |
| 券商 App 产品 | 功能数量不是短板；缺全局搜索与标的工作台、事件日历、组合体检；多数 App 功能不该抄 |

## 2. 共识诊断

1. **同一笔持仓有两套价格。** 个股页用实时报价，`PortfolioService._last_price`
   只读 `bars_daily` 最后收盘；盘中跌 7% 时持仓页还显示昨收的盈亏。止损、加仓、
   风险判断全部踩在隔夜价上——这是直接亏钱级别的错，且数据已经存在。
2. **组合层不存在。** `summary` 只到单账户，多个账户的同一只票不合并；没有跨账户
   权重、行业/市场/币种暴露、集中度；没有 NAV 序列、回撤、基准、归因。
3. **论点是叙事，不可证伪。** `theses` 有风格、赔率、证据，但没有「3–5 条可复核的
   假设（指标/阈值/复核日）」；`stop.thesis_drift` 只能比合成分项，无法在财报后
   回答「哪条假设被证伪」。
4. **估值只给一个目标价，不给价值区间。** 目标价是交易区间，不是「值多少钱」；
   没有 DCF/EPV/DDM 区间与隐含增速，买入区与安全边际无从谈起。
5. **查票入口断裂。** 全站没有搜索框；个股页只能从自选或选股结果进入；顶栏十个
   平级导航混着「对象」与「动作」；移动端没有底部 tab。
6. **发现层与执行层弱。** 规则只有 14 种（无放量/涨跌幅/涨速/触板），盘中
   `market_snapshot` 实际是盘后任务，没有涨速/量比榜；规则命中后只能标已读，
   不能就地记成交、改论点、写批注。

## 3. 现状核实（纠正三处常见误判）

- 规则模板里**没有**放量、涨跌幅、涨速、触板这几类；`stop.*`/`tp.*`/`price.*`/
  `thesis.*` 之外没有量价异动。
- `market_snapshot` 的采集在盘后 `DAILY` 任务里，不是盘中横截面；盘中只有报价板
  （自选 ∪ 持仓 ∪ 规则 ∪ 论点 ∪ 指数）。
- 个股页报价、分时、分钟 K 都是 `hx-trigger="load"` 一次性加载，不会自动刷新。
- `symbols.sector` 基本为空（A 公司概况覆盖 503、HK 3、US 0），行业暴露暂按
  「未分类」处理，不得并进「其他」。

## 4. 路线图

排序标准：先修「看着像对、其实错」的数，再补「判断依据」，最后扩「发现与执行」。
每期都给成功判据（用户能完成什么任务），不是「页面做出来了」。

### P0-1 组合盘中现价与体检（小）

- 持仓/看板/个股共用一套价格口径：盘中新鲜报价（`LIVE`/`DELAYED`）覆盖收盘价，
  行上标「现价/收盘」与来源；`STALE`/`NO_DATA`/休市回落到收盘，不拿隔夜价冒充现价。
- 持仓页合并账户视图：单票、市场、币种权重；股票内 Top5 集中度与 HHI；
  分母用 NAV（含现金），行业只对 A 可信、其余标「未分类」。
- 每一行给出「距止损 / 距目标」百分比；异常项一键生成规则（复用 D231 的建规则入口）。
- 成功判据：盘中打开持仓页，看到的价格与个股页一致；能答出「最大单票暴露是多少」；
  从发现异常到建好规则 ≤ 3 次点击。

### P0-2 事件日历与复检（中）

- 数据侧先摸清：`financials.published_date` 只有 A 股有值（A 走 `NOTICE_DATE`，
  HK/US 写 NULL）；`corp_actions` 只采到「今天」为止（`services/corp_actions.py`
  对 `until` 取 min）；公告 A/HK 有、US 无；解禁没有表。**未来 4 周没有生产者**，
  先不编造。
- 已做（P0-2a）：`/calendar` = 复检清单——我的标的（自选 + 持仓 + 推进中的论点）
  最近 30 天已披露财报与公告；「库里有财报但没有披露日」单独点名；未来一栏写清缺源。
- 下一步（P0-2b）：接一个未来事件源（A 股预约披露日优先），再做财报前 3 日待办
  与披露后「论点漂移」卡。
- 成功判据：一屏看清我的标的最近发生了什么；未来源接上后，财报后 48 小时内
  复检率可统计。

### P0-3 证伪台账（中）

- `theses` 加 3–5 条 `assumptions`：指标、比较方向、阈值、复核日、当前状态。
- 披露日或复核日自动求值，命中即告警；`stop.thesis_drift` 改比假设而非合成分项。
- 成功判据：每条论点都能回答「哪条假设被证伪、哪条还成立」。

已做（P0-3a）：

- 新表 `thesis_assumptions`（0032）+ `AssumptionRepo` + `AssumptionService`；
  论点详情页新增「证伪台账」卡：加一条、按今天判一次、删一条。
- 判定只认**截至当天**的已披露财报与最近一天估值；数据缺失是「数据不足」，
  不是「已证伪」——两者都会催人动手，但只有后者是证据。
- 用例：词表/比较 8 条、服务 7 条、页面 6 条。

已做（P0-3a / P0-3b）：见 §7 的两段「已完成」，自动判、证伪即告警、
`stop.thesis_drift` 优先比假设都已落地。

### P1 组合地基与入口（中，按依赖排序）

1. **日频 NAV / TWR / 波动 / 回撤**：先补 `cash_moves.kind`（区分外部入金）、
   公司行为入账（拆股改数量、分红进现金），再按 `sim_orders` 逐日重放；
   汇率不足时标「不可折算」，禁用 1.0。这是仓位、归因、基准的共同地基。
2. **全局搜索 + 标的工作台**：顶栏常驻搜索（代码/名称/拼音），直达统一标的页；
   页首状态带（持仓/论点/规则/最近告警/下次财报）+ 时间线；移动端底部四 tab。
3. **内在价值区间**：DCF/EPV/DDM 区间 + 反推隐含增速，假设随论点存快照；
   现价低于下沿才进买入区。
4. **买入闸与仓位建议**：收益 = 判断 × 仓位；按赔率与下行算建议仓位，
   买入表单过检查单（论点/集中度/现金），不合规只警告留痕。

### P2 归因、股息与发现层（按需）

- **股息与总回报**：由 `corp_actions` 生成股息流水，账本与复盘列「价格 + 股息 + 汇兑」。
- **业绩归因**：区间 TWR vs 同币种基准，贡献 = 期初权重 × 日收益，拆价格/汇率/现金。
- **异动榜与条件单语义**（若要短线）：涨速/量比/触板榜单（腾讯批量够用）、
  规则加有效期/once-OCO/追踪步长，告警正文生成可复制指令；真实下单永不接。
- **板块相对强弱**：先用手工行业 + 指数日线，不做概念板块与资金流实时排行。

## 5. 不做清单

| 不做 | 理由 |
| --- | --- |
| 实盘下单 / 券商接口 | 无牌照、责任不可控，会把研究系统变成交易入口 |
| Level-2 / 千档 / 逐笔 | 授权与工程成本高，对日线级研究零增益 |
| 社区 / 跟单 / 投顾 / AI 荐股 | 负价值，破坏「可解释、可复现」的定位 |
| 两融 / 期权 / 打新 / 期货 | 独立资产类别，低频高维护 |
| 龙虎榜 / 游资 / 涨停复盘 | 诱导风格漂移，与「论点—估值—风控」体系冲突 |
| 7×24 资讯流 / 研报库 | 只做持仓相关公告的定向提醒 |
| 模拟盘排行 / 收益比赛 | 真实账户镜像已够用，虚拟排名只制造纸面自信 |
| Barra / 多因子 / 组合优化器 | 4–10 只票、250 天样本，协方差误差大于信号 |

## 6. 验收方式

不用「功能数」验收，用任务验收：

- 盘中任意时刻，持仓页与个股页的价格一致，且标明「现价」还是「收盘」。
- 用户能在 3 次点击内从「某只票跌了」走到「一条针对它的规则」。
- 用户能答出：最大单票/市场/币种暴露、组合当前回撤、钱主要从哪赚来。
- 每个论点都能列出可证伪假设及其状态。
- 财报后 48 小时内，持仓与自选标的的复检没有被漏掉。

## 7. 本期落地

先做 P0-1 的第一刀：**统一盘中现价口径**（服务层接受可选报价源、页面标注来源、
`STALE`/`NO_DATA`/休市回落收盘），随后在同一页加合并暴露与集中度。

已完成（P0-1a）：

- `PortfolioService.positions/summary(..., prices=)` 接受已过闸的 `LivePrice`；
  `PositionRow.price_kind` 取 `live`/`delayed`/`close`，CLI 与调度不传时行为不变。
- `web/live_prices.py` 按 `quote_state` 与交易日历过闸；`day` 取市场本地日期。
- 持仓页与看板用同一份价格；价格格显示「现价 / 延时 / 收盘」。
- 用例：服务层 4 条、页面 4 条（含看板合计、陈旧回落、休市回落）。

已完成（P0-1b）：跨账户合并暴露、Top5、HHI、行业「未分类」

- `services/exposure.py` 是纯函数：同一 (market, code) 跨账户先合并成一只，权重分母
  取总资产（持仓 + 现金），Top5 与 HHI 也按总资产算；有效只数按持仓内部重新归一
  （否则九成现金的组合会读出「四百只等权」这种假分散）。
- 持仓页新增「组合体检」：总资产/现金占比/前五大/有效只数，市场、币种、行业三张
  分组表，加一张按权重排序的持仓表。
- 行业缺失一律标「未分类」，不并入「其他」；页面明说行业只对 A 股可信。
- 用例：`tests/services/test_exposure.py` 6 条（含跨账户同股合并、NAV 非正、缺行业），
  页面 3 条（两个账户同一只票只算一份暴露）。

待做：每行「距止损/目标」要等假设台账（P0-3）给出每只票的止损/目标来源。

已完成（P0-2a）：

- `services/recheck.py` 是纯筛选：窗口闭区间、晚于截至日的行不算「已发生」、
  没有披露日不读成「没披露」。
- `/calendar`（导航「复检」）：我的标的（自选 + 持仓 + 推进中的论点）最近 30 天
  的披露与公告；「库里有财报但披露日未入库」的标的单独列出；「预告」一栏明说
  未来事件暂无数据源。
- 用例：服务层 7 条、页面 7 条（含持仓入列、旧事件出窗、缺披露日点名单列）。

待做（P0-2b）：未来事件源（A 股预约披露日优先）、财报前 3 日待办、
披露后的「论点漂移」卡。

已完成（P0-3a）：

- `thesis_assumptions`（0032）：指标 + 方向 + 阈值 + 复核日 + 状态 + 判定读数。
- 论点详情页「证伪台账」：加一条、按今天判一次、删一条；比率类按小数填，
  页面上折成百分数。
- 判定走 `FundamentalService.read(as_of=当天)`：PIT 纪律不破；数据缺失为「数据不足」。
- 用例：词表/比较 8 条、服务 7 条、页面 6 条。

待做（P0-3b）：复核日自动判、证伪即告警、`stop.thesis_drift` 优先比假设。

已完成（P0-3b）：

  只把**刚从非证伪翻成证伪**的那几条放进报告：每趟重报等于教人忽略告警。
- 新 job `assumptions`（每市场、每日、按启用用户）：排在数据链之后，判完把证伪
