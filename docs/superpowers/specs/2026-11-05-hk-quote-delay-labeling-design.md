## 2. 为什么会显示成「停更 + 昨天」

四个事实叠起来，缺一个都不会有这一屏：

1. **没有任何适配器写过 `Quote.delayed`。** `grep -rn "delayed" src/sams/datasource/` 为空。
   这个字段是 `bool | None`，注释写得很清楚「`None` 是「没标」，不等于「保证实时」」，
   于是全场恒为 `None`。
2. **`quote_state`（`core/quotes.py:134-158`）的 `delayed` 那一支是死代码。**
   它的顺序是 `is_stale or age > stale_s ⇒ STALE`，**然后**才问 `delayed is True ⇒ DELAYED`。
   文档串里连场景都写好了：「源自己说延迟 15 分钟、而这一笔已经 20 分钟没动，
   前者是常态、后者才是要查的事」——可是没人把「源自己说」这句话送进来。
   `stale_s` 来自 `settings.quote_stale_s`，默认 **60 秒**，是给 A 股实时源定的。
   ⇒ 港股每一笔的 age ≈ 900 秒 > 60 ⇒ 全天每一刻都是 `STALE` ⇒ badge「停更」。
3. **读模型在 STALE 时优先回落日线**（`web/quotes.py:_build`：`state not in (LIVE, DELAYED)`
   且 `bar is not None` ⇒ 用日线收盘）。于是 11-04 的收盘（75.20 / +1.14%）
   顶掉了今天已经知道的 80.85 / +7.51%。**这一条才是用户看到的那个「数不对」**：
   badge 说停更，值却是昨天的，两句合起来读成「这台机器的港股同步坏了」。
4. **同一道闸把港股的盘中规则也关掉了**（`services/rules/engine.py:684`）：
   `_stale_note` 用的还是 `settings.quote_stale_s`，判据一模一样。
   ⇒ 盘中每一趟对 HK 都写「报价距今 900 秒，超过上限 60 秒：这一趟不判」。
   这条比 badge 重：**挂在美团上的止损，今天一整天不可能发出来**，而系统没有任何地方说这句话。

## 3. 设计

### 3.1 D319：延时是源的属性，由源自己声明，跟着报价走

每个报价适配器声明自己**按市场**的延时秒数，解析器把这件事写进那笔报价：

```python
# datasource/tencent.py
#: 免费端点的授权边界（11-05 实测）：A 股实时，港股固定晚 15 分钟。
QUOTE_DELAY_S: dict[str, int] = {"HK": 900}

# datasource/sina_quote.py
#: 备源实测更晚：港股约 28~30 分钟（载荷只给到分钟）
QUOTE_DELAY_S: dict[str, int] = {"HK": 1800}
```

`Quote` 加一个字段 `delay_s: int = 0`（>0 时 `delayed=True`）。放这里而不是放 settings：

* 延时属于**这一笔报价的出处**，换到新浪那一路就是 1800 秒，不是一台机器一个数；
* `quote_state` 是纯函数，多一个入参就要改四个调用点（`web/quotes.py`、
  `web/pages/dashboard.py`、`services/rules/engine.py`、`core/quotes.py`），
  而跟着 `Quote` 走只需要读 `quote.delay_s`。

新鲜度闸随之加宽——**加宽的是「这一路源本该晚多久」，不是把 60 秒改成 900 秒**：

```python
def stale_allowance(quote: Quote, stale_s: int) -> int:
    """一笔报价被判定「过期」之前允许等多久：本地阈值 + 源自己声明的延时。"""
    return stale_s + quote.delay_s
```

`quote_state` 里 `age > stale_s` 换成 `age > stale_allowance(quote, stale_s)`，
`engine._stale_note` 用同一个函数（那句话现在写的是「超过上限 60 秒」，
加宽后要说清上限是多少、以及其中 900 秒是源声明的延时）。

结果：HK 盘中 badge 从「停更」变「延迟」，那一格变成 **`14:03 延时 · 腾讯`**，
值取今天的 80.85 / +7.51%；A 股不受影响（age 4 秒 ≪ 60 秒，仍是「实时」）；
真坏的源照旧出声——腾讯那一路超过 16 分钟没有新 tick，就是 `STALE`，事故钟照走。

取舍写在这里：**港股的盘中告警从此会在一个晚 15 分钟的价上判**。
这是「晚 15 分钟通知」与「永不通知」之间的选择，不是「准」与「不准」的选择。
D120 的告警正文本来就要写出处与时刻，`_quote_line` 里那句
`if quote.delayed is True: parts.append("延迟")` 从今天起才第一次真的会被走到——
用户收到那条止损时会看到「报价 14:03:34 · 腾讯 · 延迟」。

### 3.2 D320：STALE 回落日线时，比的是**数据日**，谁新用谁

`_build` 现在的形状是「不是 LIVE/DELAYED ⇒ 有日线就用日线」。改成先比日期：

```
quote 的市场本地日 **晚于** 最后一根日线的日子 ⇒ 用报价，kind="stale"（`11-05 14:05 旧价`）
否则（同日或更早） ⇒ 用日线收盘（D232 的那道闸原样保留）
```

同日必须让日线赢：D232 说的是「收盘后 14:47 那笔盘中价没有资格叫现价」，
而当天那根收盘是权威收盘价（#373 定了收盘源）；跨日时旧的收盘比今天的最后一笔盘中价更不新，
把昨天顶上去才是这里要说的那个谎。`kind="stale"` 这条分支本来就存在（`label` 给
「11-05 14:05 旧价」），只是原来只有「库里没有日线」时才走得到——那正是
新票/退市票的形状，而「有昨天日线、也有今天盘中」这种最常见的形状被排除了。

D319 之后 HK 走不到这一支（它是 DELAYED），这一条管的是**真的**断了一截的情况：
源挂了 20 分钟，屏幕上给的是今天的最后一笔（标「旧价」），不是昨天的收盘。

### 3.3 不做的事

* **不给 `quotes_snapshot` 加延时列。** 重启灌板（`load_board`）读的是库里那 16 列，
  `delay_s` 会丢一轮——丢的那一轮 HK 显示「停更」，下一拍（实测 ≤60 秒）就自己变回「延迟」。
  为这一分钟加迁移、改写入、回填历史，收益不值。这条写进已知缺口（§5）。
* **不改 `settings.quote_stale_s` 的默认值。** 它是「本地阈值」，A 股那一路 60 秒是对的；
  需要加宽的是源那一段，而那是源的事实，不该由用户配置。
* **不动冷却与事故钟。** `QuoteService._note_outage` 只在「一个报价都没拿到」时起算，
  延时不影响它；今天 HK 每分钟都在写入，事故钟从没走过。
* **不改 `is_stale`（源自己标的不可信）**：那是另一件事，`parse_*` 在源没给可读时刻时才置位。

## 4. 验收

1. `quote_state`：`delay_s=900` 且 age=904 秒、开市 ⇒ `DELAYED`；age=1200 秒 ⇒ `STALE`；
   `delay_s=0` 且 age=90 秒 ⇒ `STALE`（A 股那条不许被加宽带过去）。
2. 解析器：腾讯 HK 夹具 ⇒ `delayed is True`、`delay_s == 900`；腾讯 A 股夹具 ⇒
   `delayed is None`、`delay_s == 0`；新浪 HK ⇒ `delay_s == 1800`。
3. 引擎（`test_rules_intraday_engine.py`）：HK 那笔晚 15 分钟的报价**参与判定**，
   命中时正文含「延迟」；晚 40 分钟 ⇒ 仍「这一趟不判」，且那句话里的上限是 960 秒而不是 60。
4. 读模型（`test_quote_view.py`）：STALE + 今天的报价 + 昨天的日线 ⇒ 显示今天的价、
   `kind="stale"`、label 含「旧价」；CLOSED + 今天盘中价 + 今天的日线 ⇒ 仍用日线收盘（D232 回归）。
5. 实机：改完重启 serve，`/watchlist` 与 `/symbol/HK/03690` 那格变成
   `80.85 港元 +7.51% 延迟 <今天 HH:MM> 延时 · 腾讯`；`/watchlist` 上 A 股那几行仍是「实时」。
6. 全量回归 + `ruff check src tests` 干净。

## 5. 已知缺口（本期不修，逐条给理由）

* **美股的延时没实测**。今天 14:18 美股休市，`field30 = 2026-11-04 16:00:01` 读不出
  「晚多少」。本轮只声明实测过的港股（`tencent HK=900`、`sina HK=1800`），
  美股一律留 0——留 0 的后果是今天这个样子（延迟被判停更），写一个没测过的数字进去的后果
  是「35 分钟没动的坏源被说成正常延迟」。今晚美股开市（北京 21:30 后）实测一次再决定，
  跟进项 #386。
* **重启后有一拍 HK 显示停更**（§3.3 第一条）：库里不存延时，灌板那一份 `delay_s=0`。
* **「延迟」这个状态目前只有一个字**。屏幕上不写「本路源固定晚 15 分钟」，
  只写 `14:03 延时`。要写成一句话就得给 `QuoteView` 再加一个来源说明，
  而 `label/detail` 两格今天已经排满了；先让人看见时刻，就知道该信几分。
* **持仓页盈亏从此用延时价**（`web/live_prices.py` 的 `delayed` 一路）：
  D232 的语义没变（休市仍回落收盘），只是盘中那一格从「昨天的收盘」变成「今天晚 15 分钟的价」。
  这是改对，不是改坏；写在这里是因为净值与盈亏的数字今晚会和昨天不同。
* 与本轮无关但同屏可见的：`task_runs` 里 HK/US 的 `actions`/`valuation` 仍在成批 failed
  （#383/#384 的范围）。
