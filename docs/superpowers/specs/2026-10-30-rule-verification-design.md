# 规则求值在网页上看得见：试算、判一次、示例（D231）

## 1. 问题

规则与告警的整条链在命令行里是通的：`sams rule check` 会打印命中/压住/判不了/没跑，
命中会写进 `alerts` 并由默认路由尝试投递。但网页上只有「新建 / 编辑 / 启停」——
用户把一条规则存进列表之后，**没有任何按钮能回答「它现在会不会响」**。调度器按自己的
节拍跑，第一次结论可能要等到下一个交易时段；一条填错阈值的规则与一条安静的规则，
在页面上长得一模一样。

结果是两个具体的困惑：

1. 「规则建完了，然后呢？」——不知道去哪看结果。
2. 「预警长什么样？」——收件箱里没有自己的告警，只剩 `/settings/test-alert` 那条与规则
   无关的测试消息。它证明通道通，不证明规则引擎通。

这一篇只补网页入口，不改求值语义、不改调度节拍。

## 2. 决定：三条路径

### 2.1 每行两个按钮：试算 / 判一次

规则列表每一行加一个表单，两个提交按钮：

| 按钮 | 表单值 | 引擎调用 | 写告警 |
|---|---|---|---|
| 试算 | `mode=dry` | `check(..., dry_run=True)` | 不写、不投递 |
| 判一次 | `mode=real` | `check(..., dry_run=False)` | 命中就写，并按默认路由投递 |

入口：`POST /rules/{rule_id}/check`，CSRF 与列表上现有的启停按钮同一道。

`mode` 只有 `real` 算真跑，其余（缺省、拼错、按回车）一律按 `dry`——**安全的默认值**：
一个没带按钮值的提交不该写告警。结果页会把「试运行：一条告警都没写」印在标题下，
不让人把试算的命中当成已经推送。

点名一条规则时引擎本来就绕过 `enabled`（`_select` 的既有语义）：停用的规则也能看
「如果开着会判出什么」，结果页另起一行说明它当前是停用的。

### 2.2 一键示例：建一条必然命中的规则并真跑一次

「不会写」比「不会点」更常见。列表顶部给一张示例卡：

- 输入市场（配置里那几个）与代码。默认取用户自选清单的第一条；没有自选就是 `A/600519`。
- `POST /rules/demo` 先读库内最新收盘（`BarRepo.last_closes`，与引擎的现价同一条口径），
  再建一条 **`stop.fixed`、止损线 = 收盘 × 1.01**（向上取到 4 位，仍不高于收盘时再加
  `0.01`）的规则。线在现价上方 ⇒ `stop_stage` 判 `hit`，这一趟必然命中。
- 规则 `enabled=False`：它是示例，不能由调度器每趟反复响。点名求值不受影响。
- 立即以 `is_test=True` 真跑一次（见 §2.4），结果页给出告警详情链接。
- 没有日线时**不建规则**：结果页直接说「这只票库里还没有日线」并给出
  `sams sync daily --market … --code …`，不留下一条永远判不了的示例。

示例名称以「示例·」开头，列表里认得出；结果页提供「删除这条示例规则」，
服务层本来就允许删非派生规则（派生规则只能停用，§9.2）。删除入口只放在示例结果页，
不给普通规则加载列表行：这是一个破坏性动作，不该长在每一行上。

### 2.3 结果页

`rule_check.html` 是试算与示例共用的出口，五摞与 CLI 的 `rule check` 同源
（`RunReport`）：

- 命中：标的名、阶段（临近/命中/紧急）、现值/阈值、建议动作、告警详情链接（真跑才有 id）。
- 压住：被哪个过滤器 / 冷却擋下，原句照印。
- 判不了：缺现价、读不到日线、老模板键等，原句照印。
- 没跑：规则展开失败（坏引用、持仓类没账户）。
- 没到：判过了但没触发。这一摞只有一个计数，页面用一句话解释它意味着「规则看过了」。

真跑的命中还要读一次 `latest_outcomes`，把「已发送 / 未配置通道 / 被抑制 / 发送失败」
印在告警链接旁：告警进收件箱与消息离开进程是两件事，这一步正是最容易混淆的地方。
没有配置任何通道时另起一句提示去哪配。

### 2.4 引擎的 `is_test`：演练告警带测试标记

`AlertSender` 端口与两个适配器（`_NotifyAlertSender`、`QueuedAlertSender`）早就收
`is_test`，只有引擎恒传 `False`。这次把 `RuleEngine.check(..., is_test=False)` 透传到
`sender.dispatch`，**只有示例演练传 `True`**；调度器、CLI、用户自己规则的「判一次」
都不传，行为一字不改。

演练告警因此在收件箱里带「测试」徽标，并且不进 `no_open_alert` 与健康积压（D131）：
它证明链路通，但不该挡住同标的的真实规则、也不该把健康页染红。它仍会走一遍真实的
投递尝试——这正是演练要证明的那一段。

## 3. 边界与失败

- 非本人的规则：`_own_view` 已有的 404，试算/判一次/删除共用。
- CSRF：三个写入口都挂 `csrf_protect`。
- `DatabaseLocked`：照既有取向原样冒到全局处理器答 503，不折成「规则不存在」。
- 引擎抛 `SamsError`（比如库写不进）：回到规则列表并带一句原因，状态码 400。
- 试算的 `Raised.alert_id` 是空串：页面只写「会命中」，不渲染一个指向 `/alerts/` 的死链。
- 示例的代码/市场先归一；归一失败按表单错误处理，不落任何行。

## 4. 测试

- 引擎：`is_test=True` 的命中落库为 `alerts.is_test = TRUE`；默认调用仍为 `FALSE`；
  试算不经过 sender（既有用例已覆盖 dry-run，不重复）。
- 页面：
  - 两个按钮把 `dry_run` / `is_test` 正确交给引擎（试算真、演练真；判一次真跑但非测试）。
  - 命中页给出 `/alerts/{id}` 链接；试算命中页不给出。
  - 压住/判不了/没跑/没到各自的原句出现在页面上。
  - 示例：线在收盘上方、规则停用、告警落库带测试标记；结果页能删掉它。
  - 没有日线：不建规则，页面给出 `sams sync daily`。
  - 别人的规则 404；三个写入口都验 CSRF。

## 5. 不做

- 不做批量「全部判一次」：一遍全市场规则的耗时不可控，按钮按下去没有进度。
- 不做前端轮询/进度条：这一趟是同步 HTTP，页面返回就是结论。
- 不改调度器频率，也不把示例规则挂进任何 job。
- 不给普通规则加网页删除按钮；删除仍走 `sams rule remove`，示例是唯一例外。
- 不把演练告警伪装成真告警：它带「测试」标记，页面明说是演练。
