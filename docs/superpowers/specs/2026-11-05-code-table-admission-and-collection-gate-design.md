## 1. 现象：一只取不到的票把三条链每晚判成失败

`task_runs` 里 11-03 之后 A 市场那几条按只循环的 job：

| job | 状态 | 次数 | 累计分钟 | note |
| --- | --- | --- | --- | --- |
| financials/A | failed | 39 | 1075 | 504/505 只财务，1 只失败 |
| flow/A | failed | 38 | 697 | 503/505 只资金流，2 只失败 |
| profile/A | failed | 35 | 596 | 504/505 只公司概况，1 只失败 |
| valuation/A | failed | 38 | 89 | 503/505 只按日估值，2 只失败 |
| actions/A | failed | 48 | 34 | 490/505 只公司行为，15 只失败 |

报错正文点到的就是那两只：

```
A 999999: [registry] A 999999 取不到按日估值。链 [...] 里被跳过的源 [...]；真调用过又失...
A 000996: [registry] A 000996 取不到资金流。链 [...] 里被跳过的源 [...]；真调用过又失败的 aksh...
```

库里这两只的形状：

- `999999`：两个用户的自选行（`sp2expert1`、`sp2expert4`，都已折起）。`symbol_master` 里**没有**
  这一行；`symbols` 里也没有；`bars_daily` 一根都没有。它是上证指数——指数不在这套系统的个股表里，
  大盘条走的是 `settings.indices` 那一组带前缀的码（D145：`sh000001`）。
- `000996`：一行**没折起**的自选。同样不在代码表、同样一根 K 线都没有；`symbol_backfills` 里
  `A/000996 / bars` 停在 `deferred`、`tries=3`——补数队列替它试过三次，每次都问不存在的源。

10-29 那次实机截下来的个股页（`tmp/expert_round2/A/page999999.html`）标题是 `A/999999`、
名字格空、正文那一句是：

> 该股数据待同步：今天已试过 3 次都没成（区间内所有源均无数据），今晚随盘后任务再试。

屏幕上这句话每天重写一遍，永远不会兑现；而它下面还挂着一个「立即排一拍」的按钮。

## 2. 根因：四道闸各问各的，代码表没被任何一道问起

| 哪里 | 现在问的是 | 出处 |
| --- | --- | --- |
| 自选准入 | 形态对不对（A 6 位数字） | `web/pages/dashboard.py:396` |
| 夜间采集 | 形态对不对 | `services/scheduler/universe.py:119` |
| 个股页可达 | 有主档行 **或** 代码表在册 | `web/pages/symbol.py:82-85`（D146） |
| 搜索能给什么 | 代码表在册（`is_active`） | `storage/repos/symbol_list.py:111` |

`symbol_master` 是唯一知道「这个市场上有哪些个股、叫什么、什么币」的那一份，由每周的
`symbol_master` job 整表覆盖（`services/scheduler/jobs.py:851`；实机在册 A 5,577 / HK 2,809 /
US 5,915，另有 6 行已关停）。形态闸（D210）挡得住「A 清单里写着 `00700`」，挡不住
「六位数字、但不是任何一只在市个股」——`999999` 与 `000996` 都是六位数字，两道闸都放行。

**代价不在那一只票取不到，而在一条链每晚被判成失败**：`_collect` 只要有一只票进 `errors`，
`JobOutcome.errors` 就非空，那行 `task_runs` 是 failed。这就是上表那 39 次失败的全部内容
——28 分钟跑完 504 只，因为一只永远取不到的票整晚标红。#380 把「到点收工」记成 ok 的同一条理由
（D311：天天被误报的链会把真故障淹掉）在这里成立得更直接：健康页读到的「财务链一直有问题」
说的是一个不存在的故障。

还有两条放大：

1. 折起的旧行也进采集清单（D169 的原话：折起那天起停更会把恢复之后的历史挖断），所以那两行
   `999999` 早就折起了，仍在 505 只里每晚被问一遍。
2. 点开那只票会排补数（D144/D283 的登记处 `SymbolInterest.ensure`），排的活注定失败；#381 刚把
   补数喘息口开进按只循环里——明知失败的活排得越勤，越吃掉真缺口的份额。

## 3. 方案：一条判据，四处使用

**判据**：一只票值不值得向源问它 = 形态对（`fits_market`）**且**代码表认得它
（该市场有一行 `is_active`）。代码表整表还没同步过时，它没有否决权。

### F1 判据只写一处

`SymbolListRepo.admits(market, code) -> bool`：

```python
if self.count(market) == 0:
    return True            # 整表未同步：这一闸不能当否决票
row = self.get(market, code)
return row is not None and bool(row["is_active"])
```

空表不否决的理由是实机顺序，不是稳妥起见：新装库第一晚代码表是空的，把空表当否决票等于
「本机什么都别采」；而 `symbol_master` 虽然排在市场组最前（`jobs.py:849`），也修不了同一个 tick 里
universe 先建、表后同步的顺序。F1 只在这一种情况下放弃判断。

批量版复用现成的 `active_codes(market)`：按市场一次取回在册代码集合。实测在实机快照上三个市场
全取 + 建 `frozenset` = **13.3 ms**（20 轮均值），一分钟一拍的 tick 里可以忽略。

### F2 自选准入（`dashboard.py:396` 那一脚）

形态过闸之后再加 F1。拒绝时的话术（不含命令行，不承诺时间）：

> 代码表里没有 A 999999：退市股、指数、或代码表还没跟上的新股都不在册。个股可在上面的搜索框按代码/拼音/名称找。

放进来才是最贵的选择：那一行会在看板上挂一个空白名字、一列破折号，和一个点开之后永远不会填上数的
链接。

### F3 夜间采集（`universe.py:119`）

与 `fits_market` 同一处、同一个去重日志（`_reported`），换一句实话：

> `%s %s 代码表里没有，已跳过采集（退市股/指数/代码表未同步到的新股）`

这一条同时管住四个来源（自选、持仓、规则目标、论点），因此 `review.py` 那个「告警加自选」的入口
（它不调 `ensure`，是四道闸里最松的一道）也不必先改——它放进来的坏码不再吃任何资源。

### F4 代码表地板（`symbol_master.py:73` 之前）

F1/F3 把「在册」变成采集的前置条件，那么「一次代码表同步把名单读少了」就不再只是搜索少几只，
而是当晚起这些票全部停更。`sync` 现在只防「全链空答复」（`kept_old`，D147）。加一条地板：
**新名单少于当前在册活跃数的一半时不关停任何行**，note 说「比旧表少一半，保留旧表在册」。
真实退市是每周几十只的量级（实机三张快照一共关停 6 行），一半的地板拦不到它。

### F5 登记兴趣不再排注定失败的活（`symbol_interest.py:77-89`）

F1 不通过时：主档行照建（否则 `SymbolInterest` 的四入口语义变），两条 `enqueue` 都不排。
`A/000996 / bars / deferred / tries=3` 那一行就是这么来的。

### F6 个股页空态的第四档

`symbol.py:162-178` 那段按队列三档说话，F5 之后「代码表不认识的票」落在「没排过队」那一档，
屏幕上会写「没有排队：点下面「立即排一拍」」——把用户支使去做一件后台已经判定做不成的事，
正是这个产品反复声明不该出现的话（模板 99 行注释自己写着「摆了就是骗人点」）。改成第四档：

> 代码表里没有这只票（退市股、指数，或代码表还没跟上的新股）：不再向源问它，也不占夜间采集。

并且 `{% if not backfill_deferred %}` 那个按钮的条件加上「代码表认得它」——F5 之后按钮点了
队列不动，必须撤掉。

## 4. 边界与不做

- **不自动折叠或删除那两行历史自选**。它们是用户的数据；F3 一挡，它们已经不吃任何资源，
  用户想清账自己点「彻底删除」。
- **不改 `review.py:100` 那条不登记兴趣的加自选口**。它缺的 `ensure` 会让新加的票缺主档行，
  那是另一条（历史上 `999999` 的自选行与主档行不一致，成因查不清：10-29 那一屏还渲染成功，
  说明当时有主档行；中间隔着 11-03 那次库损坏与还原。本条不靠考古定性，只按「现在再加一次会怎样」修）。
- **不支持把指数加进自选**。指数的地方是大盘条（D145）。
- **不把代码表从 WEEKLY 改密**：新股最多等一周。那一周内准入拒绝并说明原因，比放进清单里
  每晚失败一次好。
- **不做「遇到未知代码就顺手重查一次代码表」**：那是一条能由一次输入触发的全市场抓取。
- **不删 `symbol_backfills` 里那条 `deferred` 的 `A/000996`**：F5 之后它不会再被重新排，
  消费者读到 `deferred` 也不再拉它。

## 5. 测试

1. `admits`：空表返回 True；在册且 `is_active` True；`is_active=false` False；查无 False。
2. universe：代码表只有 `600519` 时，自选里的 `999999` 不进采集清单；同一个 builder 再 build
   一次，那句告警只出现一次。
3. universe 的回归保护：代码表整表为空时不否决（`tests/services/test_scheduler_universe.py`
   现有那些用例就是这个形状，它们必须照常绿）。
4. web：代码表有 `600519` 时提交 `A/999999` → 回原页带话，无自选行、无补数行。
5. `SymbolMasterSyncService.sync`：新名单少于在册活跃一半 → 不调用 `deactivate_missing`，
   summary 里带上那句。
6. `SymbolInterest.ensure`：代码表不认识的票 → `queued is False`、`actions_queued is False`，
   而 `created_master is True`。
7. 个股页：`A/000996` 那种「有主档行、代码表不认识、零根 K 线」的票 → 正文是第四档那句话，
   且没有「立即排一拍」按钮。

## 6. 决策

**D314** 一只票进采集清单与自选清单的准入 = 形态匹配 **且** 代码表有一行 `is_active`；
代码表该市场整表为空时这条不生效（没有否决权）。判据只写在 `SymbolListRepo.admits` 一处，
自选准入、夜间采集、登记兴趣、个股页空态四处共用。

**D315** 代码表同步加地板：新名单少于在册活跃数的一半时不关停任何行，note 明说。理由是 D314 把
「在册」变成了采集的前置条件，一次读小的名单不再只是搜索少几只，而是当晚起整片停更。
