# 选股结果到详情再回来：返回要落回原来那一屏（D229）

## 1. 问题

选股页的结果是可点的：代码与名字进 `/symbol/{market}/{code}`（D211 的「下一步是
看它长什么样」）。但详情页没有返回入口；人点浏览器的后退之外，只要再点一次导航里的
「选股」，就回到 `/screen?market=A`——条件没了，列表也没了，看一只票的代价是重选一遍。

结果本身只活在 URL 里（`market` + 重复的 `f/o/v` + `page` + `preset`），所以「回来」
不是恢复什么服务端状态，而是把进详情时那一串 URL 原样带回来。

## 2. D229：返回地址由选股页生成，详情页只认本站路径

1. **选股页把自己的 URL 交给详情页**。`_render` 用与翻页同一个 `_url` 造出
   `back_url = _url(market, rows, preset=preset, page=page)`，结果行的代码/名字链接变成
   `/symbol/{market}/{code}?back=<urlencode(back_url)>`。用 `_url` 而不是 `request.url`：
   当前请求可能带着 `notice=added`、`confirm=all` 这类一次性参数，回到那一屏时它们已经
   没有意义；翻页链接用的那一份才是这一屏的规范地址。
2. **详情页只把本地路径变成链接**。`symbol.py` 的 `_local_back` 只收以单个 `/` 开头、
   没有协议/主机、没有反斜杠与控制字符的值；其余一律当没给（不渲染返回链接）。
   `back` 会被写进 `href`，不校验就成了一个开放跳转。
3. **「立即排一拍」的回程也带着它**。空态按钮的 303 落回本页时把 `back` 重新编码带上，
   否则点一次按钮，来时的路就丢了。

入口只有选股页给 `back`，其它入口（自选、看板、提醒）的详情页保持原样——没有可靠的
「上一屏」就不摆一个假的返回键。

## 3. 验收

- 结果行的链接带 `back=`，解开后是这一屏的 `market`/全部条件/页号（或 `preset`）。
- `/symbol/A/600519?back=<本地路径>` 渲染 `← 返回`，指向该路径。
- `back=https://…`、`//host/…`、`javascript:…`、含反斜杠的值不渲染返回链接。
- `POST /symbol/…/sync?back=…` 的 303 回到带 `back` 的本页。
- 既有 web 用例全绿（自选/看板里的 symbol 链接不带 `back`，不受影响）。
