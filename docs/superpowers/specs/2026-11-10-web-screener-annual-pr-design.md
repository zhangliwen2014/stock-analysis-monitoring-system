# 选股页的可组合年报口径市赚率（D335）

## 需求

选股页要能写「A 股 PR < 0.5 且资产负债率 ≤ 0.6」这样的组合条件。页面上现有一枚
`pr_now`（现值市赚率），它的分母是 `PB ÷ PE(动)` 推出来的 ROE，随价格变，与命令行
`sams screen pr` 用的**已披露年报 ROE** 不是同一个量。要按年报口径筛，网页缺一枚字段。

## 取舍

新增一枚词表字段 `pr_annual`，由选股引擎在快照帧上调用
`analysis.fundamentals.pr(pe_ttm=…, roe=…, market=market)` 算出。不把「年报口径」
塞进 `pr_now` 的说明里，也不在页面外再开一条只跑一次的命令入口：

* 塞进 `pr_now` 会让同一枚字段在两次请求里量两件事，而屏幕上看不出来；
* 另开入口绕开词表，就等于「屏幕上能选」与「服务端认」又分叉（D179）。

`pr_annual` 与 `pr_now` 共用 `basket="pr"`：两条公式的 0.3 不是同一个量的大小，
同篮混排会让「最便宜的在前」只对组内成立（D59/D177），校验器当场拒绝。

## 字段契约

| 项 | 值 |
| --- | --- |
| name | `pr_annual` |
| label | 年报市赚率 PR |
| unit | 小数比值（0.5 = 50%） |
| source / column | derived / `pr_annual` |
| markets | A、HK、US（PE(TTM) 与年报 ROE 三个市场都有） |
| prefer | low |
| basket | pr |
| needs | `roe`、`roa`、`debt_ratio`（年报 ROE 的兜底公式要后两列） |

## 引擎

1. `_with_financials` 已经按 `needs` 把三列 join 进来；`_fill_derived_roe` 的调用条件
   从「选了 `roe`」扩到「选了 `roe` 或 `pr_annual`」——源没给 ROE 时仍按
   `ROA ÷ (1−资产负债率)` 估，口径与 `roe` 字段完全一致（D228），估算数照旧写进
   `basis_note`。
2. **只算 PE 那一支。** 命令行 `screen pr` 默认也是这样：PE 不为正时 PB 支的票会被
   排除，`--include-pb-branch` 才进来，且命中按支分组排序。网页结果表只有一个排序列，
   没有 basis 列；把两支混进一条升序表正是 D59 拦住的事。所以 PE(TTM) 不为正记「无数」
   并点名，理由里写出这条规矩。
3. 逐行调用 `pr()` 拿数与拒绝理由；拒绝理由带这只票自己的数，不能直接做分组键
   （D180：真实快照上会散成上千组）。引擎按**类**归组：
   * PE(TTM) 缺失 / PE(TTM) 不为正；
   * 没有年报（roe 为空且 roa、debt_ratio 也为空）→ 沿用 `_annual_missing_reason` 的
     按市场措辞与同步命令；
   * 有年报但兜底也算不出 ROE（roe 为空、roa 或 debt_ratio 有值）→
     `ROE_DERIVATION_FAILED`；
   * 年报 ROE 不为正；
   * 年报 ROE 达到市场口径上界（`ratio_bound`，美股 5.0）；
   * 溢出（`pr()` 已拒绝成 `inf`）。
4. 条件计数、命中行取值、排序、方案哈希、`order_note` 都走既有路径，不另写一份。

## 文案

字段 note 写清「PE(TTM) ÷ 年报 ROE ÷ 100」「PE 不为正时不改走 PB 那一支（D59）」以及
年报口径本身（A 股按披露日挡，HK/US 无披露日、按报告期取，D215/D228）。结果页
`basis_note` 复用现有两条：无披露日市场的口径说明、ROE 估算数说明。

## 验证

* 词表：字段注册、三市场可用、与 `pr_now` 同篮被拒。
* 引擎 A 股：PE 20 × ROE 0.20 → PR 1.0；与资产负债率条件 AND 后只留该留的票；
  PE 为负记「无数」且不走 PB 支；没有年报时理由给出同步命令；ROE 为负单独成组。
* 引擎 HK：源没给 ROE 时由 ROA ÷ (1−负债率) 估值算出 PR，并写进 `basis_note`。
* 引擎 US：ROE 1.714 不再撞 A 股上界（D228/D334）。
* 网页：条件行可提交、结果行同时带 PR 与其他条件值、排序说明是「年报市赚率 PR 从低到高」，
  US 页面上这一项可用。
* 串行跑相关 pytest、Ruff；用临时数据库与真实浏览器登录后跑一次组合条件，确认表格与
  无数分组；不操作生产通道。
