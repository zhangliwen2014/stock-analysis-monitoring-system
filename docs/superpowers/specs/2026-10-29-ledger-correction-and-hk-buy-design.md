# 账本纠错与跨币种买入（D205–D207）

- 来源：用户验收（2026-10-29）三条原话
  - 「买入的港股通，提示『账户没有 HKD 现金，买不了 HKD 定价的 HK 01021』」
  - 「记录的买入出现错误，比如港股通买入的，选择了 A 股，就记录成人民币，股票代码在 A 股也没有。这个也没有地方处理。录入股票代码时没有辅助提示股票名称」
  - 「如果记录错误，应该有地方可以修改」
- 范围：`/portfolio`（持仓卡片、成交记录、录入成交、现金）与 `LedgerService` / `SimOrderRepo`
- 纪律：先红后绿；每条修复都有一个「用户原话里那一屏会怎样」的测试

## D205 成交记录可撤销，撤销后按正确的重记一笔

坏的不是「录错了」，是**录错之后没有出口**：`sim_orders` 只进不出，一笔把市场记错的买入会一直
参与持仓、现金与已实现盈亏。页面上先把成交摆出来，再给一个「撤销」。

- 每张账户卡在持仓表下面新增「成交记录」表：时刻（`display_tz`，到秒）、市场/代码（链到
  `/symbol/<市场>/<代码>`，旁边是主档名称）、方向、数量、价格、费用、币种、「撤销」按钮。
- 只列最近 50 笔（新的在上），表下一句「只显示最近 50 笔」：这一屏不是对账流水，
  全量流水在现金与订单仓库里；翻页登记为待办。
- 撤销的语义是**这笔成交从未发生**：
  1. 现金反做：买入退回「数量 × 价格 + 费用」，卖出扣回「数量 × 价格 − 费用」；
  2. 该 `(账户, 市场, 代码)` 的持仓从**其余成交**按 `(ts, id)` 重放：股数累加、均价用
     `funds.blended_cost`、建仓日取第一笔买入；清仓则 `qty=0, avg_cost=0`；
  3. 删除这条 `sim_orders` 行。
- 两种拒绝（都是「这一步不让走」，不是「参数打错」）：
  - 反做后现金为负且账户无杠杆：说出余额、要动的数与结果，让用户先补钱；
  - 重放时某笔后续卖出会超卖：说出它发生在什么时候，「先撤销后面那笔卖出」。
- 端点是 `POST /portfolio/accounts/{account_id}/fills/{order_id}/undo`（带 CSRF）：
  成功 303 → `/portfolio?notice=undone`，页面顶部「成交已撤销，按正确的重记一笔。」；
  被拒 400 回原页并显示那句话。
- **为什么不直接给一个「编辑成交」表单**：改一笔 = 反做旧 + 记新。编辑表单要在一次提交里
  同时校验两边、允许跨市场换仓（旧票的持仓要重放、新票要建仓）、失败还要整段回滚，
  而且「中间那一刻」的现金够不够是个额外问题。撤销把同一组操作拆成两步，每一步都留下
  一条可核对的现金流水；页面上「撤销」旁边的那句提示就是这个工作流。
- **为什么物理删除而不是打作废标记**：`sim_orders` 没有 `cancelled` 列；留着的作废单会继续
  进 `realized_pnl`、持仓重放与规则。现金流水里的「撤销成交 <订单 id>」保留了钱的来处，
  订单本身「从未存在」比「存在但作废」更贴近要表达的事实。要留痕得加列并改所有读端，
  登记为待办。
- 服务层 `LedgerService.undo_fill(username, account_id, order_id)`：`resolve_actor` →
  `_require_account` → 仓库 → `_bump()`。仓库层 `SimOrderRepo.undo_fill(account_id, order_id,
  *, actor_id, ts)` 在一个事务里完成上面三步。

## D206 录入选票：名称候选 + 跨市场误记当场拒

用户把港股通标的挂在 A 股上，页面上没有任何东西告诉他「A 里没有这只票」，于是录进去的
是一笔人民币成交。两件事一起补：

1. **代码输入带名称候选**：录入成交的「代码」格接上已有的 `/api/symbol-search`
   （`scope=fills` 时渲染 `partials/fill_candidates.html`）：每敲一个字列出
   市场 / 代码 / 名称 / 最近收盘；「填入」把市场与代码写进成交表单（一小段页内脚本读
   `data-` 属性，不发请求）。手写仍可提交——主档没收录的新票要能记账，补数会去建主档。
2. **跨市场误记拒绝**：`record_fill` 在归一后检查——所选市场的主档没有这只票、
   而另一个**已配置市场**有它的归一代碼，就拒：
   `A 里没有 00700，但 HK 有 00700：这笔看起来记错了市场（同一只票要在它自己的市场里记）`。
   两个市场都没有 → 照收：主档未同步、新上市、退市整理都合法，
   「主档没有就拒」会把数据缺口变成记账障碍。

「最近收盘」读主档旁边的报价来源与自选页同一套（`SymbolSearchService`），不另起一条查询。

## D207 网页「换汇」：港股通先换 HKD 再买

「M3 不自动换汇」（§5.4 规则 4）没有错：自动折算会把汇率藏起来，`fx_pnl` 从此没有出处。
错的是**网页没有显式换汇的出口**，而 `sams serve` 运行时 CLI 被库锁挡住——用户照着错误提示
「先补一笔同币种现金」也走不到任何地方。

- `/portfolio` 的「现金」卡下新增「换汇」表单：账户、从币种、到币种、金额、汇率。
  汇率默认取 `fx_rates` 里当天或之前最近一条 `from→to`；只有反向那条时取倒数并标明；
  一条都没有就留空，提示可以填券商给的成交汇率，或先 `sams sync fx`。旁边显示这一行的
  日期与出处（`manual` 也照实写）。
- `SimAccountRepo.convert(account_id, from_ccy, to_ccy, amount, rate, *, actor_id, ts)`：
  - 校验：`from != to`、两个币种都在 `_CURRENCIES`、金额与汇率都大于 0；
  - 一个事务：写一行 `fx_trades`（`from_amt=amount`、`to_amt=amount × rate`）、
    两条现金流水（理由 `换汇 CNY→HKD @7.2100`）——余额、流水与换汇记录同进同退。
  - 余额不足沿用 `adjust_cash` 那句拒绝（无杠杆不透支），不在这里另写一套。
- 服务层 `LedgerService.convert(username, account_id, from_ccy, to_ccy, amount, rate)` →
  `_require_account` → 仓库 → `_bump()`；端点 `POST /ledger/fx`（CSRF）→
  303 `/portfolio?notice=fx`「换汇已记账。」。
- 买入被拒的那一句补上出口：把「先补一笔同币种现金」改成
  「不自动换汇：先在持仓页「换汇」把 HKD 换出来（填实际成交汇率），或记一笔同币种现金
  并写明理由（§5.4 规则 4）」。
- 汇率让用户可改：券商结算价与中间价本来就不一样，记实际成交价才是对账；
  自动折算不做——那正是 §5.4 规则 4 要防的。
- **仍然拆不出换汇盈亏**：订单的 `fx_rate_ref` 保持 NULL（M5 的 `fx_trades` 与订单对账
  一并做），港股持仓的 notes 会照旧说「换汇盈亏拆不出」。这笔换汇只解决「买得了」。

## 共用

- `_NOTICES` 增 `undone` 与 `fx`；被拒的撤销与换汇都回原页显示拒绝理由。
- 成交记录里的名称读 `ctx.symbols.get(market, code)`，读不到就「—」；时刻用
  `moment_label(..., seconds=True)`。
- 表单回填：撤销/换汇被拒不改动录入成交与现金表单的当前值（同 D197）。

## 测试

- 仓库：撤销买入后现金回到分、持仓消失；撤销卖出后持仓与均价回到卖出前；
  中间那笔买入被撤导致后续超卖 → 拒且什么都不动；卖出所得已花掉 → 撤销售出被现金闸拒；
- 服务：别人的成交撤不了；撤销后 `versions.bump("ledger")`（有闸时）。
- 网页：成交记录有名称与撤销按钮；撤销成功 303 带 notice；被拒 400 且成交还在；
  候选面板有名称与「填入」；A 市场录 HK 代码 → 400 点名 HK 且不落库；
  主档两边都没有的代码照收；换汇后两个币种余额与 `fx_trades` 各对得上；
  换汇后 HK 买入成功；被拒的买入那句话提到「换汇」。
