# 选股页：推荐组合、方案说明与可维护的筛选方案（D220–D222）

- 日期：2026-10-30
- 状态：设计已确认，待实施
- 关联：D179（一张词表）、D180（三个数）、D182（per-user 方案）、D188（字段按市场）、
  D217/D219（0028 展示列与报告期）、D58（库里只有小数）、D61（PIT）、D62（年报口径）

## 1. 目标

把「有一组条件，每次重新填」变成「选一个组合，看结果，存成自己的方案」：

1. **推荐组合**：把巴菲特、格雷厄姆、林奇、涅夫、格林布拉特与本站市赚率的公开
   选股原则，翻成词表里能跑的条件，连同依据与局限写在卡片上；
2. **方案说明**：用户保存的方案带一段说明/备注，列表里能直接读懂它为什么存在；
3. **可维护**：方案可以载入、重跑、编辑名字与说明、覆盖条件、删除；
4. **更会用财报**：词表补七个年报财务字段，并新增 PEG 推导，让「质量 + 估值」的
   组合不必再靠猜阈值。

不做：

- 不做推荐排序/打分，也不做「猜你喜欢」：推荐是静态配方，不是黑箱；
- 不把推荐配方写进数据库：它们是代码里的词条，所有用户看到同一份；
- 不做港股/美股选股：快照与财报口径仍只有 A 股（D188）；
- 不承诺收益。卡片上写明这是公开原则的转译，不是投资建议。

## 2. 现状与差距

- `screener_presets` 已有 per-user 增删改查、重跑、改名、覆盖、删除（D182）；
- 页面只有「重跑」能回到一条方案，没有「载入到表单」；没有说明字段；
- 词表只有价格、量、估值与 3 个年报字段；「高 ROE」「低负债」「高股息」「PEG」
  这些顶级投资者的基本门槛，大半表达不出来；
- `?preset=id` 已经会载入条件，但列表里没有入口，等于藏起来了。

## 3. 推荐组合：代码里的静态目录（D221）

新增 `src/sams/core/screener_recipes.py`：

```python
@dataclass(frozen=True)
class Recipe:
    key: str            # 稳定标识，测试与埋点用
    name: str           # 屏幕上与「存为我的方案」的默认名
    investor: str       # 出处/人物
    market: str         # 目前只有 A
    conditions: tuple[Condition, ...]
    description: str    # 一句话：筛什么
    basis: str          # 依据：这条原则从哪来、怎么转译
    caveat: str         # 局限：哪里不适用、哪里是近似
```

首批六条（全部过 `validate("A", ...)`）：

| key | 组合 | 条件（AND） | 思路 |
|---|---|---|---|
| `buffett` | 巴菲特：高 ROE 少负债 | 年报 ROE ≥ 15%、毛利率 ≥ 35%、负债率 ≤ 55% | 赚钱能力强、有定价权、不靠高杠杆 |
| `graham` | 格雷厄姆：安全边际 | PE(TTM) 介于 0.01..15、PB 介于 0.01..1.5、负债率 ≤ 50%、流动比率 ≥ 1.5 | 便宜且有资产安全垫 |
| `lynch` | 林奇：成长与价格匹配 | PEG ≤ 1、净利同比 ≥ 15% | 增长要快，价格别跑到增长前面 |
| `neff` | 涅夫：低市盈率高股息 | PE(TTM) 介于 0.01..12、股息率 ≥ 3%、净利同比 ≥ 5% | 便宜、有现金回报、仍有一点增长 |
| `greenblatt` | 格林布拉特：便宜的好生意 | ROIC ≥ 15%、PE(TTM) 介于 0.01..15 | 高资本回报 + 低估值 |
| `pr` | 市赚率：PR ≤ 0.5 | 现值 PR ≤ 0.5、年报 ROE ≥ 10% | 用本站既有的市赚率口径买赚钱的公司 |

规则：

- **配方只引用词表里的字段**；新增/改配方不改引擎；
- 每条必须能通过 `validate`，并由用例逐条钉住（字段拼错、口径混篮都会在 CI 就死）；
- 卡片同时显示条件摘要、依据与局限；「近似」必须说破（例如 PEG 用年报同比、
  格林布拉特用 ROIC/PE 近似 EBIT/EV）；
- 屏幕顶部说明：**财报条件只看快照日已披露年报的票，没有年报的票记「无数」**，
  命中数与「无数」数一起读，不把覆盖不足藏成 0 命中。

动作：

- **载入并筛选**：GET `/screen` 带 `f/o/v`，表单填好并立即跑（可继续改）；
- **存为我的方案**：POST `/screen/presets`，名字取配方的 `name`，说明取
  `description`；已存过同名方案会按既有规则报「已有同名方案」，不静默覆盖。

## 4. 方案说明（D220）

- 迁移 `0029_screener_preset_description.sql`：`screener_presets` 加
  `description TEXT NOT NULL DEFAULT ''`；
- `Preset` 多一个 `description`；`create(..., description="")`；
- `rename` 改为 `edit(user_id, id, name, description)`：名字与说明同一入口，
  `updated_at` 照旧被碰；同名规则不变；**覆盖条件不动名字与说明**；
- 说明最多 200 字，可空；空说明在列表里显示「—」，不伪造一句话；
- 页面：新建表单加「说明」；列表加「说明」列；动作改为
  「载入 · 重跑 · 编辑（名字+说明） · 覆盖为当前条件 · 删除」。

`scan_results` 的键仍是「名字 + 条件哈希」（D183）：改说明不影响历史结果的归属，
改名字或条件就是另一句话。

## 5. 词表：七个年报财务字段与 PEG（D222）

`financials` 在 0028 已有这些列，但当时明确「不进选股」。本轮把其中**有稳定年报
口径**的七列接进词表；其余展示列（金额、每股、周转率等）仍不进：

| 字段 | 标签 | 单位 | 存储列 | 口径 |
|---|---|---|---|---|
| `dividend_yield` | 股息率 | 小数（0.03 = 3%） | `dividend_yield` | 最近一期年报分红方案对应的股息率 |
| `gross_margin` | 毛利率 | 小数（0.35 = 35%） | `gross_margin` | 年报累计 |
| `net_margin` | 净利率 | 小数 | `net_margin` | 年报累计 |
| `roa` | 总资产净利率 ROA | 小数 | `roa` | 年报累计 |
| `roic` | 投入资本回报率 ROIC | 小数 | `roic` | 年报累计 |
| `debt_ratio` | 资产负债率 | 小数 | `debt_ratio` | 年报期末 |
| `current_ratio` | 流动比率 | 倍 | `current_ratio` | 年报期末 |

七列全部 `source="financials"`、`markets={"A"}`，走 `load_as_of(..., basis=ANNUAL)`
那条既有的 PIT 闸门：截至快照日已披露的最近一期**年报**，没有就记「无数」，不回退
到季报（季报累计值与年报不可比，D62）。

新增推导字段：

| 字段 | 标签 | 单位 | 算法 |
|---|---|---|---|
| `peg` | PEG（PE ÷ 净利增速） | 倍 | `PE(TTM) / (净利同比 × 100)`；PE ≤ 0 或同比 ≤ 0 记「无数」 |

`Field` 增加两个可选格：

- `needs: tuple[str, ...] = ()`——推导字段依赖的工作帧列（`peg` 依赖 `profit_yoy`），
  引擎据此把财务列传进来，避免「选了 PEG 却没 join 同比」；
- `missing_note: str = ""`——这一列无数时的固定理由（PEG 的理由不是「快照缺列」）。

PEG 的分母用**年报净利同比**，不是未来三年增速：这是可核对的近似，配方卡上写明。
负增长/亏损的公司 PEG 没有意义，直接记「无数」，不塞一个负数进排序。

0028 迁移文件里「新列不进 `screener_fields`」的注释**不修改**（迁移已应用，改注释会
破坏校验和）；本决定把它收窄为：未列入词表的展示列仍不进选股。词表是唯一入口。

## 6. 页面结构

从上到下：

1. **快照卡**（不变）；
2. **推荐选股组合卡**（新）：每行「组合 / 条件 / 说明与依据 / 载入并筛选 / 存为我的方案」；
3. **条件表单**（不变，字段下拉自动多出七列与 PEG）；
4. **结果与三个数**（不变；新增字段的「无数」理由沿用财报那句补数命令）；
5. **筛选方案卡**（改）：新建带说明；列表带说明列与「载入」；动作完整。

CSP 不变：所有动作都是普通表单/链接，没有内联脚本。

## 7. 错误与空态

- 说明超过 200 字：`ValidationError`，页面回显原文与错误，不截断保存；
- 配方名与已有方案重名：既有「已有同名方案」错误，提示改名或覆盖；
- 配方在某市场不可用：该市场不渲染这张卡（目前只有 A）；
- 没有年报的票：结果页「无数」组照旧列出原因与补数命令；
- 财务字段覆盖不足：不隐藏、不补零，推荐卡顶部固定说明这一条。
