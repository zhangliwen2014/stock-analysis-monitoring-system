## 要修的四件事

### D198 `/rules` 要能回答「这条规则在等什么、现在是什么价、上次响过没有」

列表从「名称/类型/对象/级别/覆盖/启用」扩成：

| 列 | 来源 | 说明 |
|---|---|---|
| 名称 | `rule.name` | 链接到编辑页；下方跟 `notes`（见 D200） |
| 条件 | 模板 `label` + 已存的参数 | 如「下穿指定价（价位 1200 元）」 |
| 对象 | `symbols.name` + `市场/代码` | 读不到主档就只给代码；单只标的链到 `/symbol/<市场>/<代码>` |
| 现价 | 进程级 `core.board` | 价格 + 该市场的币种 + 报价时刻 + 五态 |
| 档位 | `severity` | 中文（D201） |
| 覆盖 | `RuleView.targets` | 不变 |
| 上次响 | `alerts` 里该规则最近一条 | 没有记录写「从未」 |
| 启用 | 是/否 | 不变 |

**「上次求值时间」这一格不做**：求值结果没有落库（`services/rules/engine.py` 只写命中那一行），
在页面上编一个时间就是假话。这一格登记为待办：等盘中一趟把「上次求值的时刻与结论」落库后再上屏。
「上次响」是库里真有的最近一条告警，回答的是同一个问题的一半：它至少能区分「从没响过」与「昨天响过」。

现价读进程级行情板，不查历史日线：列表是每天打开几十次的一屏，不能为每行付一次读库。
行情板为空（服务刚起、还没轮询）就写「无行情」，不退回日线冒充实时。

### D199 未配置的市场在保存时就拒

`POST /rules/new` 带 `ZZ/600519` 现在返回 303 并落库，列表显示「启用 / 覆盖 1」，
与「读不到任何行情」矛盾。校验放在 `RuleService`（`add` 与 `edit`）：市场必须在
`settings.markets` 里，错误里列出已配置的市场。仓库层只认形状（`A/代码` 两截），
它拿不到配置；服务层是所有写入口（网页、CLI）都经过的那一层，派生写入的市场来自论，
本来就已配置。

### D200 说明行回到它自己那一行，启用/停用分两段

- `notes` 不再单起一行 `<tr colspan=7>`（它紧跟在停用规则后面，读起来像在说下一条启用的规则）；
  说明并进「名称」单元格。
- 列表按启用/已停用分成两段，段标题各出现一次；「已停用」不再靠一句重复四遍的说明。

### D201 同一套词：档位、对象、过滤器、投递结果

- 档位：`strong/mid/weak` → 强/中/弱（规则列表、规则表单、告警筛选与徽标）。
- 对象类型：`symbol/watchlist/thesis/position/portfolio` → 单只标的/自选清单/论点/持仓/组合。
- 过滤器：四个键各一句中文说明直接上屏；键名只留在表单字段名（`filter_<key>`）里。
- 投递结果：`sent/failed/suppressed/no_channel` → 已发送/发送失败/被抑制/未配置通道。
- `no_channel` 的补救指引先指向网页「设置 → 通知通道」（`monitor/router.py` 的那段正文）；
  通道加好之后规则表单才会出现通道路由多选框，最后一步才可达。

### D202 看板告警卡把两种数分开说

「今日告警 N 条」实际是今日新增（所有状态），点进去默认只看未处理，于是 1 与 0 并排出现。
卡上改成两个各自带口径的链接：

- 「今日新增 N 条」→ `/alerts?status=all`
- 「未处理 M 条」→ `/alerts`（默认 `status=new`）

### D203 保存与启停后回到列表说一句

`POST /rules/new`、`/rules/<id>/edit`、`/rules/<id>/toggle` 的 303 带 `?notice=…` 与
`#<rule_id>`：列表顶部出现「规则已保存 / 已更新 / 已启用 / 已停用」，并滚到刚动过的那一行。

## 新增的读取接口

- `AlertRepo.last_by_rule(user_id) -> dict[rule_id, (last_at, count)]`：`GROUP BY rule_id`，一趟查询。
- `AlertRepo.latest_outcomes(alert_ids) -> dict[alert_id, outcome]`：`QUALIFY row_number()` 取每条告警最后一次投递。
- `/alerts` 列表新增「投递」列，用上面那个结果；详情页同一套中文名。
