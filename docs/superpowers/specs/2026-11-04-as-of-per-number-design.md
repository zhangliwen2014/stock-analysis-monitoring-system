## 1. 这一轮要解决的到底是什么

屏幕上那句日期，读的人只会理解成一件事：**「它下面那个数是哪一天的」**。
一旦这句话说的其实是别的（读卡的那一天、库里某张表的进度、对图上有没有东西的承诺），
它就不是「标注不全」而是**标注在撒谎**——报告的原话：「标签本身错 ⇒ 比不标更危险」，
因为复盘、试算、归因的输入日全都按那句标签取，取了错的日期，后面每一步都错得看不出来。

于是这一轮只有一条规矩：

> **那句日期只能是「这个数自己的数据日」，不能是别的任何东西。**

配套的三条推论：

1. 一张卡里有几个来源，就有几个数据日；卡头那一句不能替所有来源说话。
2. 数据日与「读卡日」不相等是常态（快照 T-1、年报上一年），所以「读卡日」要么另起一句、
   要么不写，绝不能占掉数据日那个位置。
3. 一句日期不能兼职承诺「图上画到这天」——图有没有画出来是另一件事，由图自己说。

## 2. R3-04 六条的逐条判定

勘察用真库、真 HTTP（11-04 16:5x，A 股与港股都已收盘），逐条先看「标签说的是不是那个数的日子」：

| # | 现象 | 标签说的 | 那个数的实际数据日 | 判定 |
| --- | --- | --- | --- | --- |

顺带勘察到的一处同源问题（不在 R3-04 编号里，但属于同一屏同一句话）：

- 大盘条那一格只写 `实时` / `延迟` / `10-21 收盘` 之一（`state_label` 与 `index_close_label` 挤在同一格），

  「实时」那一格还顺手把「这个数是几点取的」丢了。

## 3. 五处落法

### F1 同业对比：卡头那句话拆成「来源 → 数据日」

`PeerService.compare` 已经在每一行里存了 `valuation_on`、`roe_period`、`revenue_period`，
也已经在内部算过 `snapshot_day`——**这些数据一直有，只是没上屏**。这一处不改取数，只改交出去的话：

- `PeerComparison` 新增 `snapshot_day: date | None`（市值那一列的来源日；快照不新鲜时为 `None`，
  与今天「市值不出数」是同一条判断，不多一个状态）；
- `PeerComparison` 新增 `valuation_days: tuple[date, ...]`（本卡各行估值日，去重降序）
  与 `financial_periods: tuple[date, ...]`（各行年报期，去重降序）；
- 卡头不再写「截至 {读卡日}」，改成两行：
  ```
  同业对比  金融-非银行金融-保险 · 三级行业
  市值取 11-03 快照 · PE/PB 取各行估值日（11-02 ~ 11-03）· ROE/营收取各行年报期（2025-12-31）
  ```
  估值日跨天时写区间，同一天写一天；快照不新鲜时那半句换成「市值：11-03 快照太旧，不出数」，
  与 `notes` 里那条同源，不另造一套话；
- 表里每一行的公司格补一行小字：`{valuation_on} 估值 · {roe_period} 年报`。
  为什么要到行级：中位是把 4 行不同估值日的 PE 并在一起算的，只有行级日期能让读者自己看出这个中位有多粗。

`PeerMetric.as_of` 保持原义（「这一卡算于哪一天」），模板不再把它当数据日印——
它是窗口参数，不是任何一个数的日子。

### F2 图注：把「数据截至」改成「日线库最后一根」

`_chart_caption` 现在拿 `ctx.bars.latest_date()` 拼「数据截至 {X}」。这个数是真的，
但它站的位置读起来像「这张图画到 X」。图能不能画出来只有前端知道，
而**这一轮的规矩不让一句日期兼职两件事**，所以改措术不改取数：

- `数据截至 2026-11-04` → `日线库最后一根 11-04`；
- 图本身画不出来时，那一格由 `app.js` 用 payload 的 `note` 整句替换（这条已经在了，
  11-04 实测 601318 就是这样）；两份 payload 都没 `note` 而序列为空时，
  前端仍写「这一段没有数可画。」。

这一处的取舍要说白：**不**在服务端预跑一遍 `analysis.series()` 来判断「画不画得出来」。
那等于每次渲染图局部都付一遍复权与守卫的代价，而它换来的那句话前端本来就能说。

### F3 摘要：非交易日不写行，列名改「日期」

- `DigestService.run` 加一道写入闸：`CalendarService.known_status(market, as_of) is False`
  时**不写行、不推送**，返回 `DigestOutcome(None, created=False, pushed=False, skipped_reason=...)`。
  用 `known_status` 而不是 `is_trading_day`：后者在日历没铺到那天时会给一个降级答案，
  而「日历答不上」不能变成「摘要被静默吞掉」。日历答不上（`None`）→ 照常写，
  与调度那一头的降级方向一致。
- `/digest` 列表列名 `交易日` → `日期`，页脚那句「每个交易日收盘后一条」保留。
  库里 11-01 那行是历史，不删：列名说「日期」之后它不再是假话。

### F4 选股页：快照那一行写出它管哪些列

```
快照 2026-11-03 · 票池 5577 只 · 采集 11-03 20:00
```
→
```
快照 2026-11-03 · 票池 5577 只 · 采集 11-03 20:00
下面除「价格」外的列都是这一天的数；价格列另标它自己的时点
```

价格列那一句已经逐行在标（`price_point`），缺的只是「快照日管哪些列」这个范围。

### F5 大盘条：与自选行同一个格式

`_index_rows` 给每一行两个字段：`at`（数据时点）与 `state`（市场此刻），
模板两格分别渲染——盘中是 `14:47 盘中` + `盘中`，休市回落库里是 `11-03 收盘` + `休市`。
「收盘」这个字眼仍然只在 `web/display.py` 定义（`index_close_label`），不在模板里再写一遍。

## 5. 不在本轮的两条（记下来，别当已解决）

- **②④ 的数据没追上**：`index_daily` 与 HK 日线停在 11-03，标签说的是真话，缺的是采集。
  归 D283 那条「数据不全自动补采」：开市的这一晚该由系统把指数与港美股的日线补到今天，
  而不是让人盯页面。→ 新任务，紧接本轮。
- **④ 的两根线对不上账**：同一只港股同一天，报价侧 383.60 与日线侧 388.07 差 1.16%
  （R3-06），那是 T4（#373）的权威收盘源问题。

## 6. 决策

- **D288** 屏幕上那句日期只有一个合法含义：它旁边那个数的数据日。
  卡头不许用「读卡日」替所有来源说话；一个来源一句，来源有几个就几句。
  本轮同时禁止一句日期兼职第二件事（F2 的「数据截至」兼职过「图画到了」）。
- **D289** 摘要的写入侧要有交易日闸，且判据用「日历能不能回答」（`known_status`）而不是
  「日历给的降级答案」：日历答不上时照常写，日历明确说休市时不写——
  宁可漏一条摘要，不要一条周日「收盘摘要」。
- **D290** 图局部不在服务端预跑复权序列来判断「画不画得出来」：那句话由前端说，
  服务端只说库里的进度。用一次渲染付一遍守卫的代价换一句服务端保证，不值。
