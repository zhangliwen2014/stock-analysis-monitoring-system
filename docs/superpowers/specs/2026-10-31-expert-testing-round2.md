## 1. 背景与方法

2026-10-31（周六），5 位角色独立走查 SAMS Web：价值投资者、波段交易者、组合风控、港美股用户、效率型/移动端。

| 项 | 说明 |
| --- | --- |
| 方式 | 全部实机 HTTP，记录状态码与页面原文；不读源码、不跑 CLI |
| 写入 | 只读为主。全程 3 次写：证伪台账、自选备注、规则各 1 条 |
| 数据口径 | 10-30 为最近交易日；报价是 14:28–14:47 的冻结快照，10-30 收盘 11.64（波段核对）。周六全市场休市 |
| 统计 | 27 条：P0 4、P1 16、P2 7；多源（≥2 人）10 条。R-03 经单独复现后由 P0 降为 P1（浏览器提交正常，乱码发生在裸 UTF-8 客户端与绕过修复层的写入口） |

1. **严重度按「信任/数据正确性」判，不按「页面能否打开」**。5 人均报无 5xx，沿用可用性口径会得出「一切正常」。本轮 P0 = 会让人按错数决策，或让记录不可读。
2. **周六放大了时间问题，但不是根因**。缺交易日、缺时区、试算写成 10-31，在交易日同样存在。
3. **空数据只给假设**。测试者不能看库、不能跑同步，本文只写「疑似链路/口径」；已核对设计文档处单独标注（如 D188 已注册港股 PE/PB）。

结论：无崩溃，但有 5 处会让人做错事；不先修，加功能都在漏水的桶里。

## 10. 不做清单（YAGNI）

| 不做 | 理由 |
| --- | --- |
| 原生 iOS/Android App | 问题全是布局与状态，PWA + 响应式即可；原生维护面翻倍 |
| Level-2/逐笔/盘口 | 成本高、对日线无增益；1/5 分 K 够用 |
| 实盘下单/券商接口 | 无牌照、责任不可控 |
| 社区/组合分享/收益排行 | 与「可解释」冲突 |
| 日股/英股/期货 | 港美尚有半链，先补完再扩 |
| AI 荐股/研报资讯流 | 负价值；只保留持仓公告提醒 |
| 自定义指标脚本平台 | 需求不支持，先把均线与复权做对 |
| 多租户/RBAC/团队协作 | 个人系统，权限模型拖慢改动 |

以上不影响批次 1–3；要做须单独评审。
