# 管理员数据通道与同步管理

## 需求

管理员从设置进入数据运维：查看现有数据通道、新增通道、启用/停用并查看运行状态；管理数据同步请求与执行状态。与个人通知通道明确分开，列表及管理页均有返回入口。

## 取舍

采用扩展既有 SourceAdminService、共享 AdapterRegistry 与 Scheduler 的方案。不另建独立管理系统，不把数据库配置变更伪装成已生效。另一种仅增加链接的方案不能满足新增及运行状态；重建全部采集线程的方案会中断在途任务，故不采用。

## 数据通道

- 设置顶端向管理员展示“数据通道”和“同步管理”；普通用户没有入口，所有读写端点均 require_admin，写操作校验 CSRF 并审计。
- 复用 /admin/sources，但按市场分组展示（A 股、港股、美股各一节），组内即该市场的实际降级顺序：优先级、实例名、实现、启用状态、采集健康、报价健康、最后成功日期/时刻、连续失败、脱敏错误、冷却截止时间。
- 一个源同时路由到多个市场时，在每个市场各出现一次，状态取自同一份健康记录；未路由到任何已配置市场的源单列「未路由」一节，不混进市场链。
- 每个源写出它在本市场能提供的数据类型（日线、公司行为、基本面、按日估值、资金流、公司概况、公告、个股新闻、报价、分时、分钟 K、指数日线、全市场快照、代码表等），与降级链/健康页共用同一份能力表与逐市场意愿表；不能提供的类型不列，而不是列成「无」。
- 每个市场节头写出启用中的源组成的降级顺序；停用的源仍列在组内并标「停用」，但不进入这条顺序。
- 健康未调用不能显示正常；采集和实时报价分别展示，避免一个成功掩盖另一个失败。日期级记录不得伪造精确时刻。探针结果和自动采集健康分开。
- 新增从注册目录选择实现，填写唯一实例名、支持且已配置的市场、备注与允许的 JSON 参数。未知实现/参数、重复实例名、非法 JSON/参数类型拒绝且不得覆盖已有源。参数值不回显、不写审计。
- 新源追加到市场备源链末尾；新增前验证构造成功。新增与启停持久化后更新共享注册表的后续路由，不重启服务；已有在途采集可完成，保留其适配器与健康记录引用。串行化管理变更，失败不发布半套配置。保持现有最后一个日线源的保护。
- 不提供任意代码/模块加载、任意 URL 插件或删除通道。原有探针明确只测试日线，不能把不支持日线读成故障。

## 同步管理

- /admin/sync 增加 GET 管理页；兼容现有健康页提交入口。新表单按市场与采集任务（留空表示该市场全部任务）提交，HTTP 仅入队，调度线程实际执行。
- 展示本进程手动请求：请求编号、任务/市场、提交时间、排队/已领取/执行中/成功/失败/跳过/取消、逐项结果及原因。请求结果保留最近 100 条终态记录，未结请求不丢。注明此队列是进程内状态、重启不保留；持久执行台账另列。
- 仅排队且未被调度线程领取的请求可以取消；与领取在同一锁内判定。不强杀运行中的任务。保留既有成功去重、失败冷却与单写者守卫；跳过不能宣称同步成功。
- 持久台账按市场/状态筛选、固定分页，展示任务、周期、开始/结束、结果、影响行数与脱敏错误/备注。
- 自动补数队列单列展示 pending/deferred/done、市场/代码/种类、尝试次数与原因；支持筛选分页，只对 deferred 提供单行重新排队，保留错误供诊断。创建/完成时刻不在页面展示：`symbol_backfills` 的两个时刻列按仓库既有约定不回读 TIMESTAMPTZ。不篡改成功记录，不批量重置所有任务，不将缺覆盖伪装完成。
- 同步页提供手动刷新与返回设置/通道管理/健康链接。用户可在管理后台排障，普通投资页面无需人工运行命令。

## 验证

逐行为红绿测试：源新增/重复/非法实现及参数/启停实际路由、最后源保护；请求生命周期与取消竞争、跳过及失败结果、重试暂缓记录、筛选分页；管理员授权、CSRF、错误脱敏与导航。串行运行 pytest，执行 Ruff 及 diff 检查。使用独立临时数据库启动 Web，通过真实浏览器登录、导航、新增、启停、提交/取消与查看状态，并验证普通用户不能访问。不操作生产通道、不在本次开发中重启生产服务、不读出密钥。
