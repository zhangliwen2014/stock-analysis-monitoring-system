# 市赚率（PR）与按 PR 选股 —— 设计

日期：2026-10-18　状态：M2-C 已落地（`sams analysis fundamentals` / `sams screen pr`）
相关决策：D58（小数口径）、D59（两条分支与四种拒绝）、D60（粒度分界）、D61（PIT）、D62（ROE 口径默认年报）
提出这条规则的原始要求（用户原话）：

> 市赚率公式： PR=PE÷ROE÷100， 如果PE为负数（在估值周期股和困境反转股时，可以采用现值PB搭配预估ROE） 时，
> 通过 如下公式 PR=PB÷ROE÷ROE÷100 计算。
> 增加一种 筛选股票的规则， 根据市赚率选股。比如 PR 小于等于 0.4的股票

---

## 1. 这个数在说什么

**市赚率 = 为一块钱的年利润付几块钱。**

`PE ÷ ROE ÷ 100` 里那个 `÷100` 是为「ROE 以百分数参与运算」那种写法准备的（见第 3 节）。
库里 ROE 是小数，所以 `20 ÷ 0.20 ÷ 100 = 1.00`，与「市盈率 ÷ ROE 的百分数值」同值。
刻度原点因此是 **1**：

- `PR ≈ 1`：一块钱利润收一块钱本金——市场的要价与这家公司赚钱的能力打平。
- `PR < 1`：付不到一块钱买一块钱利润。`PR = 0.4` 是「一块钱利润只收四毛」。
- `PR > 1`：为赚钱能力付了溢价。

自检例（这条公式唯一必须在单测里成立的数）：**PE=20、ROE=20% ⇒ PR = 20 ÷ 0.20 ÷ 100 = 1.00**。
实测一只真票：601088（中国神华）在 2024-07-11，PE(TTM) 14.54、2023 年报 ROE 14.52% ⇒ **PR = 1.001**。
两个数都落在 1 附近不是巧合，是这条刻度的定义所在。

**PR 低不等于便宜。** 它只说「按最近那一份已披露的年报，市场为这份赚钱能力要价多少」。
它不知道：那份 ROE 里有没有一次性收益、这家公司的 ROE 是靠多少杠杆撑起来的、
以及这个行业明年还能不能保住今年的 ROE。第 8 节把这几种误读逐条列出来。

## 2. 两条分支，以及为什么必须有第二条

`PE ≤ 0` 时市盈率本身失效（亏损公司的 PE 是负数，而「−12 倍市盈率」不是一种价格）。
要求里给的第二条公式用**现值 PB 配预估 ROE**：

```
PR = PB ÷ ROE ÷ ROE ÷ 100
```

它不是另一条独立发明的公式，而是把 `PE ≈ PB ÷ ROE` 代回原式：

```
PR = PE ÷ ROE ÷ 100 = (PB ÷ ROE) ÷ ROE ÷ 100
```

**适用场景就是要求里点名的那两类**：周期股在周期底部（利润被压到接近零甚至亏损，
PB 却已经把复苏折进去一部分）、困境反转股（账面在亏，赌的是扭亏后的赚钱能力）。
这两类恰恰是「PR ≤ 0.4」这条筛子最想捞出来的票——所以它们算不出数时必须出声，
不能被静默丢掉（D59）。

代价也写在要求里的那个词上：**预估**。第二支的分子是市场的现值 PB（有出处），
分母是人给的 ROE（没有出处）。所以：

- 两支的口径必须完全一致——同一个 ROE 定义（加权、归母、小数口径），同一个 `÷100`。
  否则两条支算出来的数不可比，而排序把它们放在同一个篮子里。
- `basis` 字段永远跟着数出门（`pe` / `pb_estimate` / `refused`），跨 basis 的 PR 不可直接排序。
- 选股默认**只扫 `pe` 那一支**；`--include-pb-branch` 才把另一支纳进来。纳进来时屏幕上
  必须有一句「这些数彼此**不可比**」，命中表**按支分组、组内升序**（PE 那一支在前），
  不是一条全局升序。
- 开关名说的是**哪一条公式**，不是说分母是预估的：`screen pr` 没有 `--roe-estimate`，
  那一支在那里用的仍是已披露那期的 ROE（`estimated=False`）。名字与排除原因都不能
  替数据撒一个不存在的数。

屏幕上的那句话（实测 000802，2024-07-11）：

```
  市赚率  PR = 1.285   ← PB ÷ ROE ÷ ROE ÷ 100，ROE=0.1500（预估，非已披露）
  ⚠ 这一支的 PR 里嵌了一个人为的 ROE 预估：它只与**同一个预估**下的数可比，不能与 PE 那一支的 PR 直接排序
```

## 3. 单位口径：这一节是整个功能里最容易静默错两位的地方

**库里只有一种比率口径：小数。** `roe = 0.20` 就是 20%，`-0.05` 就是下降 5%。
百分数 → 小数的换算只发生在采集归一那一步（`datasource/fundamentals.py` 的 `normalize_rows()`，
对着 `percent_columns` 除一次 `core.fundamentals.PERCENT_DIVISOR`），
读取侧没有任何一处 `÷ 100`（D58）。

为什么单独钉这一条：akshare 的 `ROEJQ`、增速、股息率都按百分数给（`20.0` 表示 20%），
而要求里写的算式是 `PR = PE ÷ ROE ÷ 100`——那个 `÷100` 正是为「ROE 按百分数参与运算」准备的。
两套约定撞在一起，错的那一种**不会报错**：

| 存进去的 ROE | 算式 | 得到的 PR | 屏幕上的意思 |
| --- | --- | --- | --- |
| 0.20（小数，正确） | `20 ÷ 0.20 ÷ 100` | **1.00** | 与市场要价打平 |
| 20.0（百分数，错） | `20 ÷ 20.0 ÷ 100` | **0.01** | 「极度低估」——它会排进 `PR ≤ 0.4` 的第一名 |

第三种方向同样存在：如果读取侧再除一次 100，`0.20` 会算出 100，整只票被扔进「太贵」。
所以这条口径有两重闸：

1. **词表只有一份**（`core/fundamentals.py`）：`RATIO_COLUMNS` / `MULTIPLE_COLUMNS` /
   `MONEY_COLUMNS` / `PERCENT_DIVISOR`。采集侧与仓库侧引用同一份名单，两侧各写一遍
   「哪些列要 ÷100」是这条债的原始形态。
2. **量级闸在仓库层**（`RATIO_BOUNDS`）：小数口径下 `|roe| > 5.0`（= 500%）不可能，
   最可能的解释不是「这家公司 ROE 600%」而是「百分数没换算就存了下来」。
   处置是**把那一列置空、留下这一行**——留着那个数，PR 会算出小两个数量级的「便宜」；
   置空则 PR 直接拒绝出数。**两者之间选「不出数」。**

`PE`/`PB` 是倍数，永远不参与 `÷100`（20 倍市盈率就存 20.0）。金额列是本币原值
（A 股元、港股 HKD、美股 USD），不做币种归一；币种在 `symbols.currency`。

命令行也拒绝把预估写成百分数：

```
$ sams analysis fundamentals --market A --code 000802 --roe-estimate 15
参数有误：--roe-estimate=15 不像一个小数口径的比率：要 0 < x ≤ 5（15% 写 0.15，不是 15）
```

`ratio_arg` 这道参数校验对所有比率参数生效——它的后果是「PR 静默小两百倍」，
不是排版问题。

## 4. 数据来自哪张表、哪个粒度

| 需要的数 | 表 | 粒度 | 主键 |
| --- | --- | --- | --- |
| `roe`、`revenue_yoy`、`profit_yoy`、`dividend_yield`、披露日 | `financials` | **报告期** | `(market, code, report_date)` |
| `pe_ttm`、`pb`、当日市值、当日股息率 | `valuation_daily` | **交易日** | `(market, code, date)` |
| 主力资金净流入、北向、两融 | `funding_flow` | 交易日 | `(market, code, date)` |
| 一次选股的结果 | `scan_results` | 一天一条规则 | `(date, market, strategy_id)` |

**这条分界是有意的（D60）**：比率属于报告期，倍数属于交易日。`financials` 的列名单里
刻意**不含** `pe_ttm`/`pb`——那两列在 0001 的 DDL 里确实存在，但「今天的 PE」不属于任何
一期报表，把当日倍数写进报告期那张表，等于拿一个日期冒充一个期间。

于是任何一个 PR 都由**两个不同的截至日**拼出来，屏幕上必须分别说清（实测）：

```
  采信期  2023-12-31 年报（披露 2024-03-23，源 akshare）  ROE 14.52%  营收 -0.42%  利润 -14.29%  股息率 5.01%
  估值日  2024-07-11（0 天，源 akshare）  PE(TTM) 14.54  PB 2.09  市值 8,281.20亿
```

`--as-of` 同时是这两侧的上界：它问的是「在那一天，站在那一天能看到的报表上，这只票的 PR 是多少」。

那一行的**天数**按 `as_of` 算，不按真实今天：把截至日挪回 2024 年时，PE 的陈旧程度也要跟着
回到那时候。旧过 `STALE_VALUATION_DAYS`（7 个日历日，`core/fundamentals.py` 唯一出处）时屏幕上
多一句 ⚠，因为停在几天前最常见的解释是那只票这几天停牌，而停牌期间的 PE 不是市场现在的出价（实测）：

```
  估值日  2024-07-11（52 天，源 akshare）  PE(TTM) -12.50  PB 2.89  市值 35.22亿
  ⚠ PE/PB 是 52 天前（2024-07-11）的数，旧过 7 天：这几天里那只票可能停牌，而停牌期间的 PE
    不是市场现在的出价——先 `sams sync valuation --market A --code 000802`
```

同一个 7 也是 `screen pr` 把陈旧估值放进「排除」时用的那个数：两处各写一个字面量时，同一个 PE
会在一个命令里叫「旧过」、在另一个里叫「新鲜」，而屏幕上两句都像实话（D64）。

各市场能拿到什么（实测，`datasource/capabilities.py` 是唯一出处）：**只有 A 股能算 PR**。
A 股三条链都有源（ROE 与披露日来自东财 F10 系列，`published_date` 只有它给）。
港股/美股的按日估值有源（`yfinance` 的当日快照，一个交易日一行），
但**没有任何一家给出港美股的 `financials`**：`akshare_hk` 只有分红派息（公司行为），
`yfinance` 明确不给财务指标。没有 ROE 就没有分母，港美股的 PR 于是算不出——
`--market HK` 敲下去，universe 是空的，那句「已同步基本面的 0 只」就是这条边界的声音（D38：能力比数据薄要出声）。
`published_date` 缺失同样是致命的：那一期不会被采信（第 5 节）。

## 5. PIT 规则：晚披露的数不能出现在早的那天

采信条件只有一条：`published_date <= as_of`。

- `published_date IS NULL` **排除并计数**（D61）。「我们不知道它什么时候公开」不等于
  「它不存在」，更不等于「它在那天之前公开了」——把它当成已披露，就是把未来的一期
  报表拿来解释过去的股价，这是这条公式最贵的未来函数。
- 屏幕上那一行会说清被采信的是哪一期、哪天披露的；`dropped_unpublished` 跟着 `--json` 出门。
- 同一 `(market, code, report_date)` 后写覆盖先写，而且这里**不做**跨源冲突拒绝
  （D45 那一套只属于公司行为）：同一期报表被源改过一次不是两条互相矛盾的事实，
  而是同一个事实的两次报道，谁写的记在 `source` 列里，读的人查得到。
- 粒度分界有机器守，且是**双向**的：往 `financials` 写 `pe_ttm`/`pb` 抛 `StorageError`，
  往 `valuation_daily` 写 `roe`/`revenue_yoy`/`profit_yoy` 同样抛。任何**未登记列**两侧都当场拒，
  不再由 `_prepare` 的 `select(columns)` 静默丢列——加一条采集时「写库不报错、读回来没有」
  比一次报错贵（少的那一列会一直没人知道）
  （「这一行的粒度是报告期，而倍数是某一天的数」）。D60 不靠调用方自觉。

这条规则的效果可以当场验：把 `--as-of` 从 2024-07-11 挪到 2023-01-05，被采信的年报
从 2023-12-31 退到 2022-01-01 之前的那一份，PR 从 **1.001 变成 0.588**——
一个数跟着它能看到的信息一起变，而不是跟着今天变。

## 6. 分母那一期有多长：为什么默认年报（D62）

源的 `ROEJQ` 是**该报告期累计**的加权 ROE：Q1 是三个月的，H1 是六个月的，年报是十二个月的。
分子 `PE(TTM)` 是滚动十二个月。**两者周期不同，除出来的数就在读「最近报的是哪个季度」。**

同一个 601088、同一个 PE(TTM)=14.54（2024-07-11），只换分母口径：

| 分母 | 用到的 ROE | PR |
| --- | --- | --- |
| 年报（`--roe-basis annual`，默认） | 2023-12-31 年报 14.52% | **1.001** |
| 最新已披露一期（`--roe-basis latest`） | 2024-03-31 一季报 3.54%（三个月） | **4.11** |

差四倍，而这只票什么都没变。所以：

- **默认年报**：分子分母同周期，跨票可比（这是用户确认的那句「可以设置，默认用年报？」）。
- `latest` 仍然算数，但那个 PR **只与同口径的 PR 可比**——这句话由命令打印，不靠读者记住：

```
  分母口径：ROE 取最新已披露一期的累计加权值——季报是三个月、半年报是六个月，
  而 PE(TTM) 是十二个月：这个 PR 会随最近报的是哪个季度而跳动，不能与年报口径的 PR 放在一篮子里排序
```

- 年报口径下如果库里另有更新的一期，命令会**说出来但不采信**（否则像没看见）：

```
  ⚠ 库里另有更新的一期 2024-03-31（ROE 3.54%，披露 2024-04-27）未用于 PR：
     那个 ROE 是该期累计值，与 PE(TTM) 的十二个月不同周期（要用它：`--roe-basis latest`）
```

- 代价也要说：年报口径在年报尚未披露时用的是**上一份年报**，可能滞后近一年。
  这句写在 `annual` 那条口径说明里，不藏在实现里。

`strategy_id` 里带着口径（`pr<=0.4|annual`），所以换口径不会覆盖上一次扫描的结果。

## 7. 算不出的四种情形，各自的下一步

`pr()` 只有两条分支、四种拒绝，全部集中在一处（别处不再算第二遍）。
**算不出时屏幕上打印 `PR = 无`，绝不打印 0**（D59）：0 在 PR 的刻度上意思是「免费」，
是这条公式最贵的一个误读。

| # | 情形 | 打印的下一步 |
| --- | --- | --- |
| 1 | PE 可用，ROE 缺失或 ≤ 0 | 「分母没有，PR 无从谈起——先补这只票的财务指标（`sams sync financials`）」 |
| 2 | PE 不为正/没给，PB 也缺失或 ≤ 0 | 「这一支要现值 PB 才能算（先同步估值数据：`sams sync valuation`）」 |
| 3 | PE 不为正，PB 有，但没有任何为正的 ROE（含预估） | 「这一支算的是「扭亏后能赚多少」，缺一个为正的 ROE 就没有 PR 可给（传 `--roe-estimate 0.15` 这种小数）」 |
| 4 | 库里压根没有已披露报表（读取层分诊，三种子情形） | 见下 |

第 4 种在 `FundamentalService.read` 里再分三条，因为下一步各不相同：
「既没财务也没估值」（两条采集都要跑）、「只披露到季度/半年报、没有年报」（换 `--roe-basis latest`）、
「就是没有已披露的财务数据」（只跑 `sync financials`）。实测（000802，年报口径，2024-07-11）：

```
  市赚率  PR = 无       ← A 000802 截至 2024-07-11 只披露到 2024-03-31（latest 口径下的一期），
                            没有已披露的**年报**可用：年报口径算不出 PR——传 `--roe-basis latest` 可以用那一期，
                            但那里的 ROE 是该期累计值、与 PE(TTM) 的十二个月不同周期
```

同一只票换 `--roe-basis latest` 之后，PE(TTM) 仍是 −12.50，于是走到第 3 条拒绝（Q1 ROE 为 −1.10%，不为正）：

```
  市赚率  PR = 无       ← PE(TTM)=-12.4964 不为正，PB=2.89031，没有可用 ROE 预估：
                            这一支算的是「扭亏后能赚多少」，缺一个为正的 ROE 就没有 PR 可给（传 `--roe-estimate 0.15` 这种小数）
```

再加 `--roe-estimate 0.15` 才得到第 2 节那个 1.285。这条链是有意设计的：
**一只亏损票要拿到 PR，必须有人明确说出「你认为它以后能赚多少」**，程序不许替人说。

## 8. 用法

### 8.1 看一只票

```
sams analysis fundamentals --market A --code 601088
  [--as-of YYYY-MM-DD] [--roe-basis annual|latest] [--roe-estimate 0.15] [--json]
```

默认 `--as-of` 是今天（服务层的时钟，不是请求窗口的末日）。完整输出（实测）：

```
A/601088  截至 2024-07-11
  采信期  2023-12-31 年报（披露 2024-03-23，源 akshare）  ROE 14.52%  营收 -0.42%  利润 -14.29%  股息率 5.01%
  估值日  2024-07-11（0 天，源 akshare）  PE(TTM) 14.54  PB 2.09  市值 8,281.20亿
  市赚率  PR = 1.001   ← PE ÷ ROE ÷ 100，ROE=0.1452（已披露，小数口径）
  分母口径：ROE 取最新已披露年报（12-31 那一报告期）的加权值——十二个月，与 PE(TTM) 同周期；…
  口径：比率列一律小数（0.20 = 20%），PE/PB 是倍数，金额是本币原值；ROE 按报告期、PE/PB 按交易日，两个粒度各取各的截至日
  ⚠ 库里另有更新的一期 2024-03-31（ROE 3.54%，披露 2024-04-27）未用于 PR：…
```

口径那两行由函数生成（`caliber_note()` / `roe_basis_note()`），不是散在命令里的字符串：
改口径时只有一处可改，漏改的那一处不会报错，只会继续宣布一个已经不成立的口径（D54）。

`--json` 的 payload（截断，字段全部真实）：

```json
{"status": "ok", "exit": 0, "market": "A", "code": "601088", "as_of": "2024-07-11",
 "period": "2023-12-31", "published_on": "2024-03-23", "roe": 0.1452,
 "pe_ttm": 14.53709075, "pb": 2.08533504, "valuation_on": "2024-07-11",
 "valuation_age_days": 0, "valuation_stale": false, "stale_within_days": 7,
 "source": "akshare", "valuation_source": "akshare", "dropped_unpublished": 0,
 "roe_basis": "annual", "interim_period": "2024-03-31", "interim_roe": 0.0354,
 "pr": {"value": 1.0011770488980718, "basis": "pe", "roe_used": 0.1452,
        "estimated": false, "reason": "PE ÷ ROE ÷ 100，ROE=0.1452（已披露，小数口径）"},
 "caliber": "口径：…", "basis_note": "分母口径：…",
 "warnings": ["⚠ 库里另有更新的一期 2024-03-31（ROE 3.54%，…）未用于 PR：…"]}
```

`warnings` 就是屏幕上那几行 ⚠ 的原文（D57）：不给这一项，脚本只能在中文文案里正则找「旧过」。
`valuation_age_days` 在**没有**按日估值那一行时是 `null` 而不是 `0`——「不知道几天」与
「就是今天」在选股里后果不同。

算不出 PR 时 `status` 是 `refused`、`exit` 是 1，两只票之间没有第三种「ok 但值为 null」（实测 000802）：

```json
{"status": "refused", "exit": 1, "market": "A", "code": "000802", "as_of": "2024-07-11",
 "period": null, "roe": null,
 "pe_ttm": -12.49637285, "pb": 2.89030713, "valuation_on": "2024-07-11",
 "valuation_age_days": 0, "valuation_stale": false, "stale_within_days": 7,
 "valuation_source": "akshare", "roe_basis": "annual",
 "interim_period": "2024-03-31", "interim_roe": -0.011, "interim_published_on": "2024-04-18",
 "pr": {"value": null, "basis": "refused", "roe_used": null, "estimated": false,
        "reason": "A 000802 截至 2024-07-11 只披露到 2024-03-31（latest 口径下的一期），…"},
 "caliber": "口径：…", "basis_note": "分母口径：…"}
```

`pr.value` 为 null 时 `pr.reason` 一定非空，而拒绝的那只票**仍然带着 PE/PB 与那期季度数出门**——
读的人要能看出「是哪一个数不为正挡住了这一支」，而不是一句「算不出」。参数错也是
`status: "refused"`，只是 `exit` 是 2（实测 `--roe-estimate 15`）——这个命令没有
`status: "error"` 那个出口，`--json` 下每个出口都必须是可解析 JSON。
每个出口都带与进程退出码同值的 `exit`（D57）——管道里 `$?` 会被下游命令覆盖。

### 8.2 按 PR 选股

```
sams screen pr --market A --pr-max 0.4
  [--as-of …] [--codes 601088,002450] [--roe-basis …] [--include-pb-branch] [--json]
```

**打印的第一行就是这条规则的真实边界**（不是全市场）。实测（库里有 601088/000802 的基本面，
主档只登记了 601088 一只在市）：

```
A  市赚率选股  PR ≤ 0.4  截至 2024-07-11（按日估值旧过 7 天的票进「排除」，不算落选）
扫描范围 已同步基本面的 2 只；主档只有 1 只在市——其中 1 只在主档里查不到在市记录（退市或票池未同步），PR 照算
分母口径：ROE 取最新已披露年报（12-31 那一报告期）的加权值——十二个月，与 PE(TTM) 同周期；…
命中 0 只（按 PR 升序）：
排除 1 只（算不出 PR，或按默认口径不与其他票同列）：
  000802  2024-03-31 不是年报：只披露到季报/半年报，没有已披露的年报可用（要用它：`--roe-basis latest`）
落选 1 只  算得出 PR、只是高于 0.4
口径：比率列一律小数（0.20 = 20%），PE/PB 是倍数，金额是本币原值；ROE 按报告期、PE/PB 按交易日，…
⇒ 这一篮子是空的：1 只算得出 PR 但高于门槛，1 只连 PR 都算不出——空篮子不等于「市场不便宜」
```

那句范围话有三个分支而不是两个：**样本比主档多**是会发生的（`sync financials --code` 不要求主档
有行，退市票与没同步票池的市场都落在这里），而把它说成「范围外的 -1 只」是一句反话——
把「主档不认识这几只」说成了「主档里还有几只等着被覆盖」。

universe 的定义写在 `services/screen.py::pr_max` 的第一行注释里，也打在屏幕上：
**库里 `financials` 有行的全部代码**（`financials.synced_codes`，不带披露日、不带口径、不带截至日）。
它刻意**不**按当前 `--roe-basis` 划，也**不**按「有已披露一期」划：一只只有季报的票确实在库里，
年报口径下算不出 PR 是**要被点名的排除**，不是「这只票不在样本里」——后者会把它从那句
「已同步基本面的 N 只」里静默消失，而它正是这条规则最想问的那类票。披露日全为 NULL 的那只同理：
它需要的是「我们不知道它何时公开」这句点名。`valuation_daily` 缺行进排除而不是消失。
一只都没扫成（universe 为空）时退出码是 **1** 而不是 0，打印的是「这条命令的输入是同步过的票，
不是全市场」——扫过而空与压根没得扫是两个事实（实测 HK：库里没有 HK 的基本面源，那一篮子恒空）。

三条容易被漏掉的分类规矩：

- **命中/落选/排除是三堆**，不是两堆。`priced_out`（算得出 PR 但高于门槛）与
  `excluded`（连 PR 都算不出）混成一堆「不满足」，就等于把这条规则最想捞的困境反转股丢进沉默里。
  对账等式 `len(hits) + priced_out + len(excluded) == universe_size` 由用例守着。
- **`--codes` 里点了名、库里一行都没有的代码进第四堆 `unmatched`**：它们不属于上面三堆里的任何
  一堆（压根没进范围），硬塞进排除会让那条等式不成立，而静默少吃一只是这条命令最贵的一种错。
- **PE 不为正因而没有 PR 的票单独点名**（`排除 …`）：静默丢掉一只正是最需要出声的。
- **陈旧估值进「排除」而不是命中**：默认 7 天（`stale_within_days`，与 `analysis fundamentals`
  同一常量，见 D67）。停牌票的旧 PE 算出的 PR 不属于今天这一篮子，但它也不该被算成
  「这只票不便宜」——它只是今天没有答案。

门槛的校验与比较：`--pr-max` 必须是**有限**的正数，且在比较精度下不能 round 成 0
（`PR_SCALE_DECIMALS = 6`）。`float("nan")` 不抛、`nan <= 0` 是 False，它会一路走进 payload，
那里 `"threshold": NaN` 已经不是合法 JSON；而 `0.0000004` 会被写成与 0.0 比较——
0 在 PR 的刻度上意思是「免费」，是这条公式最贵的一个误读（§7）。
比较本身是 `round(pr, 6) <= round(threshold, 6)`：门槛写在命令行上就是要能被正好敲中，
`PR = 0.4` 必须入、`0.41` 不入。`--as-of` 晚于今天时当场拒绝（`archived` 那条是另一回事）：
「截至那天已披露」这道闸门在未来那天上是永真的，那不是更宽的窗口而是一次未来函数（D9）。

结果按 `(market, strategy_id, 那一天)` 覆盖写入 `scan_results`（不追加行），`hits_json` 里
每行都带 `basis`、`roe_used`、`period`、`valuation_on`、`estimated`。M3 的通知层拿到的
就是这个，而不是一个裸的 code 列表。

**`--codes` 子集扫描不写存档**（`archived: false`，屏幕上带一句 ⚠）。`strategy_id` 里刻意不含
codes：把 codes 编进 id 会让「今天这一篮子」变成 N 行试跑，通知层从此不知道读哪一行；
不含 codes 则第二次试跑会覆盖全量那一条而屏幕上不发生任何事。两个契约里选了后者并承担它
的代价——子集结果只上屏、不落库。

### 8.3 先要有数据

```
sams sync financials --market A --code 601088     # 报告期财务指标（默认起点 1990-01-01）
sams sync valuation  --market A --code 601088     # 按交易日的 PE/PB
sams sync flow       --market A --code 601088     # 资金流（A 股单源；HK/US 没有能对上能力的源）
```

`sams health` 报的是**只数**而不是行数：`financials = 400 行` 可能是 200 只票两期，
也可能是 2 只票 200 期，而这两种库里能算 PR 的票差一百倍。

## 9. `PR ≤ 0.4` 这个门槛的含义与局限

0.4 是用户给的第一个参数，不是我们验证过的常数。它能筛出「赚钱能力强而市场要价低」的票，
前提是下面这些坑你一个个看过：

1. **分母是一次性收益的载体**。一年卖掉一栋楼，ROE 从 8% 变 30%，PR 立刻从 2.5 掉到 0.7。
   这个数没有告诉你是哪种；要判断得回到 `revenue_yoy`/`profit_yoy` 与利润表本身。
2. **高 ROE 可能来自杠杆**。银行、地产、部分非银金融的 ROE 长期 12–15%，而它们的
   PB 常年 0.5–0.8，PR 于是稳定地低。低 PR 在这里读作「市场对这份杠杆定价」，
   不是「便宜」。跨行业比 PR 需要先比 ROE 是怎么来的。
3. **预估支的分子是人的乐观**。`--roe-estimate` 给多大，PR 就按它的平方倒数变小
   （`PB ÷ ROE ÷ ROE`）：0.15 → 1.285，0.30 → 0.321。同一只票，只差一个念头，
   就从「落选」进「命中」。这就是默认只扫 `pe` 那一支、混进来要分组并写明不可比的原因。
4. **年报口径可能滞后近一年**。一家刚掉头向下的公司，PR 仍按去年那份漂亮的年报算。
5. **累计口径的周期错配**（第 6 节）。换 `latest` 而不换篮子，就是把「reporting 日历」读成「便宜」。
6. **universe 只是已同步的那些票**。`PR ≤ 0.4` 扫出 0 只，第一件要确认的事是
   「库里同步了几只」，而不是「市场贵不贵」。这是 U24，排程化留下一个全市场采集任务后才能消。
7. **PR 不含时间维度**。ROE 是**最近那一份**，不是趋势；连续三年 ROE 从 25% 掉到 12% 的票
   可以有一个很好看的 PR。M2-D 的估值分位与 `revenue_yoy`/`profit_yoy` 是补这一条的接缝。

## 10. 与 M2-D 估值合成的接缝

这条链现在交付的是**一个可解释的截面数**：任何一只票、任何一天（只要那天之前披露过年报）、
PR 是多少、用的是哪一期的哪个数、出自哪一家源。M2-D 要接的是两件事：

- **历史分位**：`valuation_daily` 已经把按日的 PE/PB 存下来了，「现在的 PE 在五年里排第几」
  是这条序列上的读取用例；PR 的历史序列同理可算（同一只票按 `--as-of` 逐日重放）。
  分位的对照表由 M2-D 定（U9 仍开放）。
- **基本面分位**：`financials` 里 `roe`/`revenue_yoy`/`profit_yoy` 的同期历史就是这个的原料。
  PR 会是那儿的输入之一，而不是结论——第 9 节那些坑，每一个都要在合成层各自被点名。

`scan_results` 是 M3 通知层的入口：一条规则、一天、一份带 `basis` 的命中清单。
